**No PDL field is introduced here.** Library `part.yaml` gains optional `frames` and `frames_source` (library schema, validated by `part_errors`); the bay is an ordinary schema-0.3 `cavities` entry on the host component; the op writes `position` and `rotation_deg` of the servo (existing fields).

Ordering: edits `core/hangar/geom/library.py`, a new op module and `knowledge/parts`; no wing or tail generator is touched, so U15.1, U16.2 and S6 do not collide. S4 needs the `output` frame this brief adds.

## What is wrong today
Servos sit on the skin: fraction of each servo volume inside its host, measured by W34-A: C172 wing servos 0.26, A400M 0.09-0.29; the C172 tail servos are 1.00 inside a SOLID fuselage loft (buried, invisible). Cavities work on generated parts (`core/hangar/geometry.py:91`, `_apply_cavities`) but nothing writes one for a servo. A servo part is an envelope box (23 x 11.5 x 24 mm for `emax-es08maii-metal`, local bounds x +-11.5, y +-5.75, z +-12, centred) with no output shaft position, so every arm pivot is a hand-typed coordinate.

## Decision (default taken)
- `part.yaml` optional keys, both required together when `frames` is present:
  ```
  frames:
    output: {point: [x, y, z], axis: [x, y, z]}      # servo output shaft: a point on it and its direction pointing OUT of the case, part-local frame (same frame as geometry)
    mount_face: {point: [x, y, z], normal: [x, y, z]}  # the plane the ears sit against and its OUTWARD normal (toward the shaft side), part-local
  frames_source: <text>                                # where the numbers come from; "estimate" is allowed, a measured value names the drawing or measurement
  ```
  `part_errors` checks: each `point`, `axis`, `normal` is 3 numbers, `axis` and `normal` are non-zero and axis-aligned (exactly one non-zero component), `frames_source` is a non-empty string, `frames` only for `category: servo`.
- `emax-es08maii-metal/part.yaml` gets `frames: {output: {point: [5.5, 0, 12.0], axis: [0, 0, 1]}, mount_face: {point: [0, 0, 5.5], normal: [0, 0, 1]}}` and `frames_source: "estimate: typical 9 g servo layout (shaft about 6 mm from one end of the case, ears about 6.5 mm below the shaft face); the retailer page gives only the 23 x 11.5 x 24 mm envelope; replace when measured"`. No other part changes.
- Op `design.place` (CLI `plane design place`): `plane design place DESIGN COMPONENT --in HOST --at X,Y --face lower|upper [--shaft X,Y,Z] [--clearance MM] --why TEXT`. Defaults: `--shaft` = outward normal of the chosen face (lower = `0,0,-1`, upper = `0,0,1`); `--clearance` = `standards/gate-thresholds.yaml` entry `bay_clearance_mm` (new, value 0.3, `source: pending`, note `provisional bay clearance; no published source opened (U16.1 S3)`).
  Algorithm (all in the body frame; the host must have no `rotation_deg`, else input error):
  1. COMPONENT must be `geometry: {generator: library_part, params: {part: P}}` and part `P` must have `frames` (else input error naming the part). `--shaft` must be axis-aligned.
  2. Rotation: among the roll/pitch/yaw triples with each angle in {0, 90, 180, 270} (convention of `geometry.rotation_matrix`: R = Rz Ry Rx), pick the one with `R @ output.axis == shaft` (to 1e-9) and `R @ mount_face.normal == shaft` (the mount normal and the output axis are parallel by construction here), minimising the sum of the three angles, ties broken by the largest roll, then the largest pitch, then the largest yaw (so the antiparallel case gives `[180, 0, 0]`, not `[0, 180, 0]`). No triple: input error.
  3. Skin height: cast a vertical ray at `(X, Y)` through the host's UNCUT mesh (the host without its cavities: build `component_parts` of a copy of the host with `cavities` removed): `--face lower` = the lowest hit z, `--face upper` = the highest hit z. No hit: input error `no host surface at (X, Y)`.
  4. Position: the servo `position` is chosen so that the rotated `mount_face.point` lies at `(X, Y, skin_z)`: `position = (X, Y, skin_z) - R @ mount_face.point`.
  5. Bay: the servo's rotated axis-aligned box (rotate the 8 corners of its local bounds, take min and max) clipped to the host side of the skin plane (for `lower`: z >= skin_z; for `upper`: z <= skin_z), grown by `clearance` on every side except the skin side, where it is extended by 1.0 mm beyond the skin so the cavity opens through the surface. This box in the host's local frame (subtract the host `position`) is appended to the host's `cavities` as `{geometry: {box: {size: [...]}}, position: [...], description: "bay for <COMPONENT>"}`. A cavity with that description already on the host is replaced (the op is idempotent).
  6. Writes: `components[COMPONENT].position`, `components[COMPONENT].rotation_deg` (omitted when `[0, 0, 0]`) and the host cavity, in ONE atomic edit through the existing text-edit code (`hangar.pdledit`, `hangar.ops.edit._write_with_log`, as `design.add` and `design.set` do: byte-preserving, schema-checked, logged in CHANGELOG.yaml with `--why`). Use `hangar.ops.call("design.set", ...)` with `also` for the position and rotation, and `pdledit` text helpers for the cavity list; if one atomic write is not possible report which helper blocks it (stop rule).
  7. Result data (all rounded to 4 decimals): `position`, `rotation_deg`, `skin_z`, `output_point` and `output_axis` (the frame in the body frame: `R @ output.point + position`, `R @ output.axis`), `cavity` (the written mapping), `removed_mm3` (volume of the cavity box inside the uncut host mesh, `hangar.checks._overlap_volume`), `body_inside_fraction` (the part of the servo on the body side of the rotated mount plane: its volume inside the uncut host divided by its volume; compute with `_overlap_volume` of the servo mesh clipped by `trimesh.intersections.slice_mesh_plane(..., cap=True)` and the uncut host mesh).
- Out of scope (state in the PR): arm slot cavities (S4 or the design may add them), a servo that is not axis-aligned, bays for non-servo parts, a bay through a host with `rotation_deg`, removing a bay (delete the cavity with `design set --kind remove`).
