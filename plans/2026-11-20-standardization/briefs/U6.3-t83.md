What the diff does (behaviour is fixed here; do not change it):
1. `FAIL_ONLY_CRITERIA` changes from `{id: "one criterion"}` to `{id: [criteria...]}` (a list, first is the primary, the one in `data["criterion"]`), because some ids carry more than one criterion in `checks.py`. It now holds the 8 ids that `checks.py` emits only with status FAIL: `T0.version`, `T0.unique_ids`, `T0.attachment_refs`, `T0.root` (all `schema/plane.schema.json`, no number behind it so `threshold` is `null`), `T1.attachment_contact` (`attach_tolerance_mm`), `T1.attachment_overlap` (`embed_max_fraction_of_child`, `glued_overlap_max_fraction`), `T1.attachment_location` (`attach_tolerance_mm`, `schema/plane.schema.json`), `T4.machine` (`manufacturing.yaml`).
2. `explain` copies the list (`criteria = list(FAIL_ONLY_CRITERIA[check_id])`); nothing else in the op changes. Without `--design` the tier-level answer is unchanged. An unknown id is still refused with exit 2.
3. The old guard test `test_fail_only_criteria_ids_are_emitted_only_as_fail_in_checks_py` is replaced by `test_fail_only_criteria_table_matches_checks_py`, which scans `checks.py` for every id whose literal status is only `FAIL` and requires that set to equal the table keys (so a new FAIL-only id, or one that gains a PASS, fails the test), and that each listed criterion appears in `checks.py`.

Defaults taken (T83 leaves these open; stated here, tested below):
- Only ids with a literal id string and only-FAIL statuses in `checks.py` are listed. Not listed, on purpose: `T4.fits_machine` (emits SKIP too, and its criterion is per machine), `T9.claims.load` (in `gates/claims.py`, emitted only when claims.yaml fails to load, its tier has no rows on a design without claims), mixed-status ids such as `T2.joint_load`, and dynamic ids (`T6.mechanism.<id>`, `T7.wiring.<id>`, `T8.bom.line.<id>`, ...).
- A criterion without `#` (a schema path, `manufacturing.yaml`) gives `threshold: null`; the renderer already prints only the criterion line then.
- `docs/cli.md` and the op summary do not change (no new parameter).
