## Why (recorded red on main, 2026-11-24)
`plane design set <d> "components[new]" --value ... --kind add` -> "name a scalar value, not a list element"; `components[1]` -> "index 1 out of range"; `bom.items[bom-x].part_number --kind add` (bom is a one-line flow mapping) -> "cannot add this value without rewriting other text; edit the file by hand". `plane design add` -> `No such command 'add'`. No op appends a whole element, so a design cannot be built from the CLI.

## Interface (exactly this; no other public names)
1. `core/hangar/pdledit.py`: `def append_element(text: str, key: str, element: dict) -> tuple[str, list, list]` returning (patched text, old list, new list). `key` is a dotted key naming a list (`components`, `attachments`, `bom.items`, `wiring.harnesses`); selectors like `[id]` or `[0]` -> OpInputError `"<key>: name the list by its key"`.
   - `element` must be a non-empty dict with a string `id` that fullmatches `hangar.ids.ID_RE`; else OpInputError `"<key>: element needs a string id matching <ID_RE.pattern>"`. An id equal to an existing element's `id` -> `"<key>: id '<id>' already exists"`.
   - Missing key -> OpInputError `"<key>: no such list; create it first with: design set <key> --kind add --value '[{...}]'"`. Key that is not a list -> `"<key>: is not a list"`.
   - Block list (lines starting `- `, any indent; comments and blank lines between elements allowed): insert directly after the last line of the last element (find it with `_block_end(lines, start, dash_col, False)` as `remove_element` does). If the last element is a one-line flow entry (`- {...}`), the new entry is one line `<dash>- ` + `render_flow(element)`. Otherwise a block entry: first line `<dash>- id: <render_scalar(id)>`, then one line per other key at column dash+2 as `key: ` + `render_flow(value)`, in the dict's order.
   - One-line flow list (`key: [...]`, including `[]`, also inside a flow mapping such as `bom: {items: [...]}`): reuse the adding branch of `_edit_list` but render the item with `render_flow(item)` instead of `render_scalar(item)`. Behaviour of `append_item` for scalars must not change.
   - Multi-line flow list -> OpInputError with the existing "edit the file by hand" wording.
   - Verify as `add_value` does: `yaml.safe_load(out)` equals old data with the element appended at `key`; every `difflib` opcode against the original is `equal` or `insert` (flow case: exactly one replaced line); else OpInputError `"<key>: adding would rewrite other lines; edit the file by hand"`. Preserve CRLF as the neighbours do.
2. `core/hangar/ops/edit.py`, new op placed after `set_op`:
   ```python
   @op(name="design.add", summary="Append one element ({id: ..., ...} as a one-line {mapping}) to a list such as components, attachments or bom.items (byte-preserving; id checked; the whole element is schema-checked before anything is written) and log it in CHANGELOG.yaml.", mutates=True, render=lambda r: "\n".join(r.messages))
   def add_op(path: str, key: str, *, value: str, why: str) -> OpResult:
   ```
   Steps: `plane = _plane(path)`; empty `why` -> OpInputError "why must not be empty"; `element = pdledit.parse_value(value)`; not a dict -> OpInputError `"value must be a {mapping} with an id"`; `working, old, new = pdledit.append_element(text, key, element)`; then the same three guards `set_op` runs: fresh `expression_errors`, `pdledit.check_schema(before, after, key)`, `regeneration_report(text, working, plane)` (refuses when the edit newly breaks a generated part; nothing written). Log entry `{"date": stamp, "key": f"{key}[{id}]", "old": None, "new": element, "why": why, "kind": "add"}` appended to CHANGELOG.yaml with the same list/EOL handling as `set_op` lines 126-139: copy them into a private helper `_write_with_log(plane, text, working, entries)` used ONLY by `add_op` (do not touch `set_op`). Return `OpResult(True, {"key": key, "id": id, "index": len(old), "changed": True}, [f"{key}[{id}]: added"], changed_files=[str(plane), str(log)])`; when `regeneration_report` lists components, add the same `regenerated ...` message line `set_op` builds.
3. CLI `plane design add <path> <key> --value '<mapping>' --why '<text>'` and MCP tool `design_add` come from the op registry; do not edit `cli.py` or `mcp_server.py`. Studio (`viewer/`) is out of scope.
4. Regenerate `docs/cli.md`.
