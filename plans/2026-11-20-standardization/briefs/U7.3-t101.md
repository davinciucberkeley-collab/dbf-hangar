1. `_map_args` mapped every non-option word that names an existing path, so a `--why`/`--value` text or a KEY naming a path (`--why concept-a` run from `ws/designs`) was rewritten or refused and a legitimate run failed. New `_path_positions(argv)` finds the words that are declared path arguments of the op the first two words name (an `argument` parameter named `path` or `src`, or of type Path: `design set PATH`, `design copy SRC`); `_map_args` maps only those. 2. `PLANE_BENCH_LOG` pinning. The log grows during the run, so its content cannot be pinned by a digest as the snapshot is. What `replay` now pins: the log must lie outside the workspace (message `the plane command log is inside the workspace; cannot replay`), and every line must be exactly what `cli._log_invocation` writes: an object with keys `argv` (a list of strings) and `cwd` (a string) and no other key, else the existing message `the plane command log is unreadable; cannot replay`.
3. `design.sweep` wrote `.sweeps/` into the real repo during a bench run (it is a read-only op for `replay_kind`, so it runs unreplayed). New `_sweep_root()` in `edit.py`: `SWEEP_ROOT` normally; when `PLANE_DESIGNS_DIR` is set (the bench runner sets it) the `.sweeps` folder next to that `designs/` folder, i.e. inside the workspace.
4. `tree_digest` docstring says an added empty folder goes undetected.

NOT in this brief: the one paid `bench run` that probes shell redirection under `Bash(plane *)` (ledger T101, second item). It stays open in the ledger; do not run `bench run`, do not call `claude`.
