## Interface for other units (quote word for word; U1.3 and later units code against this)

Everything below lives in `hangar.ops` (`core/hangar/ops/__init__.py`). Op modules are any `core/hangar/ops/<name>.py` that does not start with `_`; `registry()` imports all of them automatically (pkgutil), so a new unit adds a file and edits no registry list.

```python
from hangar.ops import op, OpResult, OpInputError, registry, call

@op(name="design.migrate", summary="Migrate a design to PDL v1.0.", mutates=True)
def migrate_op(path: str, *, write: bool = False) -> OpResult: ...
```

- Decorator: `op(name: str, summary: str, mutates: bool = False, adapters: tuple[str, ...] = (), render: Callable[[OpResult], str] | None = None)`. `name` is `<group>.<verb>`, matching `^[a-z][a-z0-9]*\.[a-z][a-z0-9-]*$`. A duplicate name raises `ValueError`. The decorator registers the function and returns it unchanged. `render` is optional and only used for human (non-`--json`) CLI output.
- Op function: plain Python function, annotated parameters, returns `OpResult`. Supported parameter types: `str`, `int`, `float`, `bool`, `pathlib.Path`, `Literal["a", "b", ...]` (string values only), `list[str]`. Any other annotation raises `TypeError` when the decorator runs. A missing annotation also raises `TypeError`.
- Mapping to click (done once, in `cli.py`):
  - Parameter with no default and not keyword-only (before any `*`): click ARGUMENT, required, in declaration order. `list[str]` here is `nargs=-1`, not required.
  - Parameter with a default, or keyword-only without a default: click OPTION `--<name>` (underscores become hyphens; one trailing underscore is dropped, so `format_` is `--format`). Keyword-only without a default is a required option.
  - `bool`: with default `False` a flag `--name`; with default `True` a `--name/--no-name` pair. A bool without a default raises `TypeError`.
  - `Path` becomes `click.Path()` with no existence check (the op reports bad paths itself). `Literal` becomes `click.Choice` of its values. `list[str]` option becomes `multiple=True`. `int`/`float` become `click.INT`/`click.FLOAT`.
  - Every generated command also gets `--json` (flag). With `--json` stdout is exactly `OpResult.to_json()` plus one newline, nothing else. Without it: errors go to stderr as `plane: <message>`, otherwise the op's `render(result)` text (default: the messages one per line, or, if there are none, the `data` as indented JSON) goes to stdout.
- `OpResult` (dataclass): `ok: bool`, `data: dict`, `messages: list[str] = []`, `changed_files: list[str] = []`, `skipped: list[str] = []`; class attribute `schema_version = "1.0"`; `.to_json() -> str` (indent 2, keys in this order: `schema_version, ok, data, messages, changed_files, skipped`; numpy and Path values are converted); property `.exit_code -> int`: 0 if `ok`; else 2 if `data.get("error") == "input"`; else 1.
- Errors: an op that cannot do its job because of bad input (unreadable design, unknown id, bad value) raises `OpInputError(message)`; `call()` turns it into `OpResult(ok=False, data={"error": "input"}, messages=[message])` (exit 2). An unexpected exception becomes `OpResult(ok=False, data={"error": "internal"}, messages=[f"{type(e).__name__}: {e}"])` (exit 1), never a traceback. A failed check (the op ran, the answer is "no") is `ok=False` with no `error` key (exit 1).
- `registry() -> dict[str, OpSpec]` sorted by name; `call(name: str, **params) -> OpResult` (unknown name raises `KeyError`). `call()` keys are `ParamSpec.name`, the Python parameter name (e.g. `format_`, never `format`). `call()` converts and checks every parameter against its ParamSpec and returns the exit-2 result above on any failure: unknown or missing parameter; `str` to `Path`; `Literal` membership; `list`/`tuple` to `list[str]`; `int`/`float`/`bool` accepted from `str` too (`bool` accepts `true/false/1/0/yes/no`, case-insensitive). So the CLI, MCP and Studio all get the same validation; the CLI callback passes raw click values.
- Each click parameter is declared with the Python name as its destination, so kwargs reach `call()` unchanged: `click.Option(["--format", "format_"])` (name list first, then the destination), `click.Argument(["new_id"])`.
- `OpSpec` (frozen dataclass): `name, summary, mutates, adapters, func, params: tuple[ParamSpec, ...], render`; properties `group`, `verb`. `ParamSpec` (frozen dataclass): `name, cli_name, type_name, kind, required, default, choices, multiple` where `type_name` is one of `"str","int","float","bool","path","choice","list[str]"`, `kind` is `"argument"` or `"option"`, `choices` is a tuple of str or `None`.
- Schema: `schema/op-result.schema.json`; `hangar.ops.OP_RESULT_SCHEMA_PATH` is its Path.
- Op modules never import `hangar.cli` at module level; anything from `hangar.cli` is imported inside the function body (cli imports ops, so a top-level import would be circular). Op modules that use `Path`, `Literal` or `list[str]` in annotations import them at module level (`from pathlib import Path`, `from typing import Literal`): `get_type_hints` resolves names from the module globals even with `from __future__ import annotations`.

### Step 3 `core/hangar/ops/__init__.py`
Implement exactly the "Interface for other units" section. Details the builder must follow:
- Use `typing.get_type_hints(func)` and `inspect.signature(func)`; classify `Literal` via `typing.get_origin(t) is Literal`, `list[str]` via `get_origin(t) is list and get_args(t) == (str,)`.
- `_build_spec(func, *, name, summary, mutates, adapters, render) -> OpSpec` does validation and builds specs without registering; `op(...)` calls it, then registers into a module-level dict (duplicate name raises `ValueError`) and returns `func`.
- `registry()`: on first call import every non-underscore submodule of `hangar.ops` with `pkgutil.iter_modules(__path__)` + `importlib.import_module`, then return `dict(sorted(_REGISTRY.items()))`. `call()` and everything that needs ops use `registry()` so modules are loaded.
- `call(name, **params)`: look up spec (`KeyError` if unknown); compare `params` with the declared `ParamSpec.name`s: any unknown or missing-required name returns the exit-2 `OpResult` (messages like `unknown parameter 'bogus'` / `missing parameter 'path'`); apply declared defaults; then convert and check each value per its ParamSpec (str to Path; Literal membership, message `invalid value 'x' for 'tier': choose from 0, 1, ...`; list/tuple to list; int/float/bool from str; a failed conversion is `invalid value ...`), any failure returning the exit-2 result; run the function inside try/except `OpInputError` and `Exception` as specified; if the function returns something that is not an `OpResult`, return the internal-error result.
- `OpResult.to_json()` uses `json.dumps(..., indent=2, default=_jsonable)` where `_jsonable` converts `np.ndarray` to list, `np.generic` to `.item()`, anything else to `str(o)`.
- `OP_RESULT_SCHEMA_PATH = Path(__file__).resolve().parents[3] / "schema" / "op-result.schema.json"`.
