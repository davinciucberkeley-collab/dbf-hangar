# Brief U13.8-1-pending-thrust: `propulsion.max_thrust_n` may be `pending`, every reader skips with a reason

class: hard · role: builder-plus · plan: §7 U13.8 (rehearsal 4 gap 1, c172-rc, PR #9) · depends on: nothing · merge order: 1st · SLUG = `pending-thrust`

Environment: follow `plans/2026-11-20-standardization/briefs/U13.7-env.md` with every `u13.7` read as `u13.8` and SLUG=pending-thrust.

## Why (red on main, 2026-11-25)
The motor `propulsion` block requires `max_thrust_n` (schema `$defs/component.propulsion.required = ["max_thrust_n", "axis"]`, number > 0). The MN3510 library page gives power and current only, no thrust, so rehearsal 4 wrote the placeholder `1` ("not a rating") because nothing allows "unknown". A made-up number passes every check silently; the repo rule is to leave unsourced values `pending` and let checks SKIP with a reason. Red: `design set components[motor_l].propulsion.max_thrust_n --value pending --why t` on a copy of `designs/example-tailsitter-wing` fails the schema (`'pending' is not of type 'number'`).

## Rule (the only definition)
`max_thrust_n` is either a number > 0 or the string `pending`. A pending thrust is an unknown, never 0 and never 1: every value derived from it is NOT computed, and the check that needs it is a SKIP row whose message contains `max_thrust_n is pending` and the motor ids. Nothing that does not need the thrust changes; a design without `pending` is bit-identical.
