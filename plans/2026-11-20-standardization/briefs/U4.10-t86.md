What the diff does (behaviour is fixed here; do not change it):
1. `registry()` rolls back, after a failed module import, only the ops whose function is defined in that module (`_REGISTRY[added].func.__module__ == "hangar.ops.<module>"`). Before, it dropped every op added during the import, including the ops of another ops module the failing one had imported: that inner module stays cached in `sys.modules`, never re-runs on the retry, so its ops were lost for good. The `duplicate op name` guard in `op()` is unchanged; the failed module's own ops are still removed so a retry does not trip it.
2. `test_registry_keeps_the_ops_of_a_module_that_a_failing_module_imported` builds `zz_a_outer.py` (imports `zz_b_inner`, registers `zz.outer`, then raises) and `zz_b_inner.py` (registers `zz.inner`) in `tmp_path`, so the registry loads the outer one first (alphabetical). After the failure `zz.outer` is gone and `zz.inner` stays; after the retry both are registered. The `finally` removes both ops, both `sys.modules` entries and both package attributes, like the existing T3 test.
3. Two harness tests in `tests/test_gates.py`, both in strict mode on `base()` with `esc` and `battery` turned into point masses: `harness esc -> [battery] -> body` has one point-mass-to-point-mass segment (not checked) and one checked segment: PASS, message holds `all 1 checked segments` and `1 segment(s) between point masses not checked`. `harness esc -> [battery] -> far_pod`: the checked segment `battery` to `far_pod` leaves every envelope, so FAIL with `segment battery to far_pod`; the point-mass segment must not hide it (W6-R J6#2 variant).

Defaults taken (the ledger text leaves these open): the key is the function's module, as W6-R suggested, not a comment that records the assumption. No change to the other T86 sub-items. No change to `integration.py`.
