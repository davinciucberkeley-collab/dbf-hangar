## Design (fixed; do not revisit)
- New option `--deflection D` (registry name `deflection`, float, default `15.0`, degrees per side). The target gate ratio is `r = D / input_range` (default `15 / 20 = 0.75`).
- `--arm-length` (registry `arm_length`) changes default from `6.0` to `None`. When a number is given it wins: `--deflection` is then ignored for the construction (and only the achieved deflection is reported). When `None`, the arm length is solved as below.
- Solve (module constants and helper named exactly): `DEFLECTION_TOL_MM = 1e-9`, `DEFLECTION_MAX_ITER = 50`, helper `_solve_arm(pin0, Op, a_o, side, P, ax, ratio, W) -> float`, all numpy:
  1. `lever(L)`: `tip = _tip(pin0, Op, a_o, L, side)`; `u = unit(pin0 - tip)`; return `abs(u . (ax x (pin0 - P)))` (`ax` the unit hinge axis, `P` the hinge point at the station). At neutral the arm is square to the rod, so the gate's small-angle ratio is exactly `L / lever(L)`.
  2. Fixed point: `L = 6.0`; repeat up to `DEFLECTION_MAX_ITER`: `Ln = ratio * lever(L)`; if `abs(Ln - L) < DEFLECTION_TOL_MM` return `Ln`; `L = Ln`. If `L >= W` at any step or the loop ends without converging raise `OpInputError`. (Fixture: converges in 7 iterations.)
  3. `pin0`, `Op`, `a_o`, `side`, `P`, `ax`, `W` come from a first `_geometry(...)` call made with `arm_length = 6.0` (add `P` and `ax` to the dict `_geometry` returns, and `W` = `|w|` as `_tip` computes it; add it to the dict as `W`). Then call `_geometry` again with the solved `L` so every written point is consistent with the final arm. (The pin sign `sg` depends on the arm only through the side the rod comes from; if the second call's `pin0` differs from the first by more than 1e-6 mm, stop and report: it did not on the fixture.)
- Error texts (contain the quoted words): D not positive: `--deflection must be positive`; solved arm at or above `W`: `deflection {D:g} deg needs an arm of {L:.2f} mm, longer than the distance from the servo shaft to the horn pin ({W:.2f} mm); lower --deflection, raise --input-range, or give --arm-length`; no convergence: `deflection {D:g} deg: the arm length did not converge; give --arm-length`. All via `OpInputError` before anything is written, file unchanged.
- Achieved deflection, added to `data` (and the first message line, see below): after the existing `simulate_mechanism(final, fm)` call take the steps at input `+input_range` and `-input_range` (they are in `sim["steps"]` with `input_deg` as float). `follower_deg` = `{"plus": f(+in), "minus": f(-in)}` signed, rounded to 3 decimals; `deflection_deg` = `round((abs(plus) + abs(minus)) / 2, 2)`; `arm_length` = the arm length used, rounded to 4. When the simulation raised or has no such step (a jam stopped it) all three are `None`. `ratio` is unchanged: the gate's value rounded to 2 decimals.
- First message line: unchanged text plus `, deflection {deflection_deg:g} deg` appended before the `; unchanged` suffix, only when `deflection_deg` is not `None`.
- Nothing is written to PDL for the option (no field): an identical re-run writes nothing; the arm length ends up in the strut and attachment coordinates only. Re-running with another `--deflection` replaces the four elements in place as today.
- Update the op summary string: add "The arm length is solved from `--deflection` (default 15 deg per side at the input range) unless `--arm-length` is given; reports the achieved deflection."
- Existing designs are unchanged until add-linkage is re-run on them.
