## Exact steps and outputs
### 1. `viewer/vp/status.js` (pure)
- `rowParts(row, parts)` -> `string[]`: `parts` is the fetched `parts.json` (`{parts, attachments}`), `known` = set of its part ids. Collect from `row.data`: `component` (string) ; `parts` (array of strings); `pair` (array of exactly two strings) ; `joint` (string, or array of strings) mapped through `attachments` by `label` to `[parent, child]` ; `link_pairs` (array of two-id arrays, flattened). Keep only ids in `known`, unique, in first-seen order. Strings with spaces or `&` are ignored (old index files). A row without any of these -> `[]`.
- `partStatus(scorecard, parts)` -> `Map<id, { status: 'FAIL' | 'WARN', rows: [{check_id, status, message}] }>`: over every row of every tier with status `FAIL` or `WARN` whose `rowParts` is non-empty; a part's status is the worst of its rows (FAIL over WARN); `rows` keeps every FAIL/WARN row naming it, FAIL first. SKIP and PASS rows are ignored for colour.
- `partChecks(scorecard, parts, id)` -> every row (all statuses, FAIL, WARN, SKIP, PASS) naming `id`, FAIL first (`STATUS_ORDER` from `lib.js`), for the inspector.

### 2. Colour modes (`materials.js`, `scene.js`, `index.html`)
- Select `<select data-testid="colour-by">` in the tool/view bar of `.vp-wrap` with options `type` (default), `status`, `mass`; label "Colour by". `Viewport.colourBy(mode)` (also the hook) stores `this.colourMode` and calls `applyAppearance` (B3).
- `type`: as today (vertex colours on, `material.color` white). `status`: parts in the status map get `material.vertexColors = false` and `material.color` `0xdc2626` (FAIL) or `0xf59e0b` (WARN); all other parts `0x9aa3b2` with `vertexColors = false`. `mass`: every part with a mass (`mass.per_component`, B2's fetch) gets a colour from a linear ramp light blue `0x9ecbff` (lightest part) to red `0xb91c1c` (heaviest) by `mass_g / max_mass_g`; parts without mass `0x9aa3b2`. Set `material.needsUpdate = true` when `vertexColors` changes. Propellers keep their alpha handling. Selection tint (emissive) and ghost/dim rules from B3 still apply on top.
- Legend: `<div data-testid="legend" class="vp-legend2">` inside `.vp-wrap`: status mode: three swatches `FAIL`, `WARN`, `no finding` plus the counts of coloured parts; mass mode: the ramp with `0 g` and the heaviest part's mass (`fmt(max, 0) + ' g'`); type mode: hidden (the CG legend of today stays).
- `state()` (B2) fills `coloured`: status mode -> ids with FAIL or WARN; mass mode -> ids with a mass; type mode -> `[]`; plus `colourBy: <mode>` and `status: { id: 'FAIL' | 'WARN' }`.
- `Viewport.setStatus(map)` is called by `designs.js` after the scorecard is fetched and again whenever the scorecard is re-fetched (after a re-check); changing the design resets `colourMode` to `type`.

### 3. Tree dots (`ui/tree.js`)
Each row gets `<span class="status-dot" data-status="FAIL|WARN|">` (empty value when no finding; NOT the class `dot`, which `style.css` already uses for the orange CG marker) and the row carries `data-status` with the same value; the status shows in all colour modes. Dots use the same red/amber as the model.

### 4. Scorecard rows (`modes/designs.js`)
- Row ids: `ids = rowParts(r, partsJson)` (fetch `getJSON(d.parts)` once, with the scorecard). A row with `ids.length` gets class `has-parts`, `data-parts="a|b|c"`, `tabindex 0`, `role button`, `data-testid="check-row"`, `data-check-id="<check_id>"` (every row gets the two data attributes, with or without ids), and a hint `show <ids joined by " + ">` (class `partshint`, truncated after 3 ids as `+ N more`). The previous `pair`-only logic and `has-pair` class are removed, as is the `.active` toggling in `app.js` `setHighlight`.
- Click or Enter on a row with ids: `vp.focusParts(ids)`: saves the current ghost set once, selects `ids`, ghosts every other drawn part (`setGhost(all - ids, true)`), calls `fitTo(ids)`, and marks the row `.active`. Clicking the same row again, or `Escape`, calls `vp.clearFocus()`: selection cleared, the saved ghost set restored, view kept. A different row replaces the focus (the saved ghost set is kept, not re-saved).
- Compare mode is unchanged (`setHighlight` behaviour for the two compare viewports is untouched).

### 5. Inspector checks (`ui/inspector.js`)
For one selected part add a `Checks (N)` section (`<ul data-testid="part-checks">`, one `<li>` per `partChecks` row: status badge, `check_id`, message). N counts rows. Clicking an `li` scrolls the matching scorecard row into view (`[data-check-id]`) and adds `.active` to it. Re-rendered whenever the scorecard is re-fetched (so after B5's Apply and the check job the moved part shows its fresh T1 rows). Nothing selected: the section is absent.
