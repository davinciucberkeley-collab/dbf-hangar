- What the logs show: only the text `Failed to load resource ... 404 (Not Found)`; Chromium's console text carries no URL, so the log cannot say which file. Windows saw three, ubuntu one. The studio serves exactly three per-design files that a page fetches after reading `data/index.json`: `<fid>.glb`, `<fid>.scorecard.json`, `<fid>.mass.json` (`app.js` `Viewport.show` and `modes/designs.js` `renderScorecard`).
- Root cause (inferred from the code; not reproduced: the test passed 2 of 2 runs on a fast machine): `Studio._job_check` deletes every `<did>-*` result file that is not the new version's right before it publishes the new entry. A page that fetched `index.json` (or still holds it in `state.index`) just before a re-check finishes then asks for the previous version's glb, scorecard and mass after they are gone: 404 for each, on a slow runner more of them than on a fast one. In this test the re-checks come from `design.set` (save) and `design.propose` (the fake `git switch main` rewrites `plane.yaml`, then `scan()` queues a re-check), while the page keeps rendering. Nothing is retried and no console error is hidden.
- Fix (real, in the server): keep the previous version's files for one more re-check. `_job_check` now deletes only files that belong to neither the new version nor the version in `self.cache[did]["hash"]` (the one being replaced). Files two versions back are still deleted, so the folder cannot grow.
- Diagnostic (not a filter): `collect(page)` now appends the URL to each console error (`m.location['url']`), so if a 404 ever recurs the assertion names the file. `assert errors == []` is unchanged: no error is ignored.
- Not changed: the viewer JS, the poll interval, the test's waits. If CI still shows a 404 after this lands, the new message names the URL; report it, do not widen the test.
