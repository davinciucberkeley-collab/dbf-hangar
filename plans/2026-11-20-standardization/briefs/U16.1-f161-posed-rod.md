## Problem (W34-T5, main 7b5d764)
T1 poses (`core/hangar/checks.py` `tier1_geometry`, loop over `_configurations(...)`) move each joint alone: a driven surface (e.g. the elevator) swings while the arm stays at 0, or the arm swings while the surface stays at 0. The pushrod is a child of the arm, so it is rigid with the arm only. `_contact_and_clash_checks` then drops every pair "rod x part moved by this configuration" into one `T1.kinematic_link` SKIP row (`checks.py` near the comment "kinematic_link children are moved by a linkage"). On c172-rc that is 7 SKIP rows. The S1 four-bar solve already gives the true rod pose: `solve_four_bar`, `rod_transform`, `link_overrides` in `core/hangar/gates/mechanisms.py` (T6 and `mechanism_sweeps` use them; T1 does not).

## Decision (taken; do not redesign)
For each configuration T1 samples, if a `kinematics: four_bar` mechanism with a `link` has exactly one of {driver angle, driven angle} nonzero in that configuration, complete the pose so it is mechanically consistent and pose the rod:
- driver nonzero, driven 0: driven angle = `solve_four_bar(tip0, pin0, drv, fol, d, fol_range)` (the existing solver);
- driven nonzero, driver 0: driver angle = `solve_four_bar(pin0, tip0, fol, drv, f, drv_range)` (the same solver with the two ends swapped: the rod length is symmetric);
- no root within the range (the surface angle is unreachable with this arm range), or both nonzero, or both zero: leave the configuration exactly as it is today (the SKIP stays, it is honest: that pose cannot happen through the linkage).
The rod then takes `link_overrides(design, mech, d, f)` (rod and everything downstream of `link.driver_end`). Pairs whose rod is posed this way are checked like any other pair. Do NOT change `mechanism_pose_angles`, `geom/sweeps.py` (cut-pose sweeps keep their own configurations), T6, `mechanism_sweeps`, `_configurations`, or the SKIP row text.

```python
def consistent_four_bar_pose(design: Design, angles: dict[str, float]) -> tuple[dict[str, float], dict[str, np.ndarray]]:
    """T1: complete a configuration in which a four_bar mechanism has exactly one of its driver and driven joints off 0
    by solving the other from the rod length. Returns (angles, rod overrides: component id -> 4x4); a mechanism with no
    solution within the ranges, or with both or neither joint off 0, is left as given (no override)."""
    out, ov = dict(angles), {}
    for mech in design.data.get("mechanisms", []) or []:
        if mech.get("kinematics") != "four_bar" or not mech.get("link"):
            continue
        try:
            tip0, pin0, drv, fol = _four_bar_geometry(design, mech)
        except (KeyError, TypeError, IndexError):
            continue
        dl, fl = mech["driver"], mech["driven"][0]
        d, f = out.get(dl, 0.0), out.get(fl, 0.0)
        if (abs(d) > 1e-12) == (abs(f) > 1e-12):
            continue
        d_rng = (float(drv["range_deg"][0]), float(drv["range_deg"][1]))
        f_rng = (float(fol["range_deg"][0]), float(fol["range_deg"][1]))
        if abs(f) <= 1e-12:
            t = solve_four_bar(tip0, pin0, drv, fol, _clamp(d, d_rng), f_rng)
            if t is None:
                continue
            f = t
        else:
            t = solve_four_bar(pin0, tip0, fol, drv, f, d_rng)
            if t is None:
                continue
            d = t
        out[dl], out[fl] = d, f
        ov.update(link_overrides(design, mech, d, f))
    return out, ov
```
