## Decisions
- decided (conductor default, 2026-11-21): one `design.set` call per Save, first changed field as `key`/`value`, the rest in `also` (atomic: all or none), one `kind` and one `why` for the whole Save.
- decided (conductor default, 2026-11-21): `kind` select options `modify` (default), `subtract`, `add`; `why` is a required one-line text input in the edit dialog footer area; no second dialog.
- decided (conductor default, 2026-11-21): Validate runs the default tier (`design.validate` with no `tier`), shows the result in a panel inside the scorecard column under the button bar, and keeps it until the design is saved or another design is chosen.
- decided (conductor default, 2026-11-21): Propose asks for a title only (default `Edit <design id>`), calls `design.propose`, shows the returned `pr_url` as a link in the same panel area; the link renders as `<a>` only if it matches `^https?://`.
- decided (conductor default, 2026-11-21): the two removed routes are deleted, not kept; `STUDIO_DIR/backups` is no longer written (git and `CHANGELOG.yaml` are the history); the `BACKUP_DIR` constant stays because tests monkeypatch it.
- decided (conductor default, 2026-11-21): the browser test mocks `hangar.ops.edit._run` (git and gh calls), not the op, so the real `design.propose` code path runs.

## Facts from merged code (do not re-derive)
- Ops (from `core/hangar/ops/edit.py` and `design.py`; HTTP route `POST /api/op/<name>`, JSON body keyed by public param names, `map_params` strips a trailing `_`):
  - `design.set(path: str, key: str, *, value: str, why: str, kind: "add"|"subtract"|"modify" = "modify", also: list[str] = None)`. `also` items are `"KEY=VALUE"` strings. `value` is parsed with `yaml.safe_load` (`pdledit.parse_scalar`). It writes bytes (keeps CRLF/LF and comments), appends to `<design dir>/CHANGELOG.yaml`, returns `OpResult(True, {"key","old","new","kind","changed","changes":[{key,old,new}]}, messages)`. Empty `why` raises `OpInputError` (HTTP 400, body `ok: false`). A missing key with `kind != "add"` is an error.
  - `design.validate(path: str, tier: "0".."5"|"all" = "5")`: `ok` is false when the card has failures, but HTTP status stays 200 (400 only for input errors). `data` = `{design_id, accepted, partial, max_tier, tiers: [{tier, name, status, results: [{check_id, status, message, criterion, data}]}], markdown}`. **`data.markdown` uses the tier status per row (ledger T25); never render it. Render `tiers[].results[]` and each row's own `status`.**
  - `design.propose(path: str, title: str)`: returns `OpResult(True, {"pr_url", "branch"}, [url])`; runs git/gh through `hangar.ops.edit._run(argv: list[str], cwd: str) -> str` and `_gh() -> str`; `mutates=True`, so the server calls `studio.scan()` after it.
  - Response body of every op: `{schema_version, ok, data, messages, changed_files, skipped}`.
- Key syntax (`core/hangar/pdledit.py::parse_key`): `name`, `requirements.<k>`, `components[<id>].mass_g`, `components[<id>].manufacturing.method`, `components[<id>].position[0]` (also `[1]`, `[2]`), `attachments[<id>].rated_load_n`. The `path` argument accepts the design folder (`ping.designs_dir + '/' + id`, as `edit.js` already does for `design.get`).
- `viewer/lib.js` exports `h, $, fmt, getJSON, api, opCall, cache, TIERS, STATUS_ORDER`. `opCall(name, params)` posts to `api/op/<name>` and **throws** when `body.ok` is false, returns `body.data` otherwise. A failing validation therefore needs a non-throwing variant.
