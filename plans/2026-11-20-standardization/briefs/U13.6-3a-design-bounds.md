## Why (red on main)
`plane design bounds` -> `No such command 'bounds'`. The C172 rehearsal had to export a GLB (metres, y-up) and load it with trimesh in a scratch script to learn where parts are; servo and horn placement needs numbers in the design's own frame (mm, +x aft, +y starboard, +z up).

## Exact steps
1. In `core/hangar/ops/design.py` add, directly after `mass_op`:
```python
@op(name="design.bounds", summary="Bounding box of every component in the body frame (mm, neutral pose): min, max, size and centre; point masses give their point. Use it to place parts against each other.", render=...)
def bounds_op(path: str) -> OpResult:
```
   Load the design as `mass_op` does (`_load(path)`); for each component in file order: a point mass (`is_point_mass(c)`, as `export.to_scene` imports it) -> `{"id", "type", "point": [x, y, z]}` from its `position`; otherwise `parts = component_parts(c, design.base_dir)` (from `..geometry`), `lo = min over parts of mesh.bounds[0]`, `hi = max of mesh.bounds[1]` (numpy, each rounded to 3 decimals, lists of floats) -> `{"id", "type", "min": lo, "max": hi, "size": hi - lo, "center": (lo + hi)/2}`. A component whose geometry fails to build -> `{"id", "type", "error": "<message>"}` (never raises for one component). Data `{"components": [...], "overall": {"min", "max", "size"}}` where `overall` spans every non-error, non-point component (`null` values when there are none).
2. The `render` lambda prints one line per component: `id  type  min=[...]  max=[...]  size=[...]` (numbers with one decimal), point masses as `id  type  point=[...]`, errors as `id  type  ERROR: <message>`, then a last line `overall  min=[...]  max=[...]  size=[...]`.
3. Regenerate `docs/cli.md`.
