## Exact steps and outputs
1. `knowledge/parts/<part-id>/part.yaml` format (write it as `knowledge/parts/README.md`):
```
id: <slug, equals the folder name>
name: <string>
category: motor|propeller|esc|battery|servo|flight-controller|receiver|gps|sensor|connector|fastener|structure|other
vendor: <string>
part_number: <string>
url: <http(s) url>
mass_g: <number > 0>
dimensions_mm: [x, y, z]            # envelope, part-local frame
cad_status: vendor-cad | representative-envelope
cad_source: <string: URL of the vendor CAD, or where the envelope came from>
verified: {by: <string>, date: 'YYYY-MM-DD', method: <string>}
geometry: {generator: <registered generator>, params: {...}}   # same shape as a component's geometry; file paths resolve against the part's folder
```
2. `core/hangar/geom/library.py`:
   - `PARTS_DIR = REPO_ROOT / "knowledge" / "parts"` (`from hangar.design import REPO_ROOT`); tests monkeypatch it, so every function reads `PARTS_DIR` at call time.
   - `REQUIRED = ("id","name","category","vendor","part_number","url","mass_g","dimensions_mm","cad_status","cad_source","verified","geometry")`, `CATEGORIES`, `CAD_STATUS = ("vendor-cad","representative-envelope")`.
   - `part_errors(data: dict, folder_name: str) -> list[str]`: missing keys, `id != folder_name`, bad category, bad cad_status, `mass_g <= 0`, `dimensions_mm` not 3 positive numbers, `url` not starting `http`, `verified` missing `by`/`date`/`method`, `geometry` without `generator`.
   - `list_parts() -> list[str]` (sorted folder names that contain `part.yaml`); `load_part(part_id: str) -> dict` (raises `KeyError(f"unknown library part {part_id!r}; known: ...")`, and `GeometryError` listing `part_errors`); returns the dict plus `"_dir": Path`.
   - Generator `library_part` registered with `register(Generator("library_part", {"part": ParamSpec("string", required=True, doc="id of a knowledge/parts/ entry")}, build, check=check))`: `check(p)` returns `[f"part: unknown library part {p['part']!r}; known: {', '.join(list_parts())}"]` when missing; `build(p, base_dir)` loads the part and returns `registry.build_component({"id": part_id, "geometry": part["geometry"]}, part["_dir"])`; `files` stays the default `[]`.
3. `ops/parts.py`: `@op(name="parts.list", summary="List the real-parts library (knowledge/parts/).", render=...)` returning `OpResult(True, {"parts": [{"id","name","category","vendor","part_number","mass_g","cad_status"}...], "count": n})` with an optional `category: str = ""` filter (unknown category -> `OpInputError`); `@op(name="parts.show", ...)` taking `id: str`, returning the full record (without `_dir`), unknown id -> `OpInputError`. Follow the style of `core/hangar/ops/standards.py::connections`.
4. Schema: `bom_item.properties.library_part`: `{"$ref": "#/$defs/slug", "description": "id of a knowledge/parts/ entry; T8 checks it exists."}`.
5. `sourcing.py::tier8_sourcing`: for each BOM item with `library_part`: `PASS` row `T8.bom.library.<item id>` message `f"{item}: library part {part} ({cad_status})"`, `data={"parts": [...component_ids], "cad_status": ...}`; part missing -> FAIL `"{item}: library part {part} not in knowledge/parts/"`. For each component whose `geometry.generator == "library_part"`: find the BOM item whose `component_ids` contains it; none, or its `library_part` differs from the component's `geometry.params.part` -> FAIL row `T8.bom.library_match.<component id>` message `"{cid}: 3D model is library part {x} but its BOM line {y} says {z}"` (`y` = item id or `none`); else PASS. Use `hangar.geom.library.load_part` lazily inside the function. Criterion constant stays the existing `CRIT` of that file.
