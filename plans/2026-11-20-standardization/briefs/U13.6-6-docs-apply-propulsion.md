## Exact steps
1. `docs/team-guide.md`, section `### Starting a new concept`: directly after the bullet that starts `- Airfoils:` insert these three bullets (same `- ` style):
```
- Many edits at once: `plane design apply <path> --edits <file.yaml> --why "..."` applies a YAML list in one step (one regeneration pass, one CHANGELOG entry; all or nothing). Each item has one verb key and, except `remove`, a `value` written as YAML data (not as a string): `- {set: "components[wing].mass_g", value: 250}` changes an existing scalar or an existing one-line list such as a position (`value: [212, 0, 0]`); `- {add: flight.cl_max, value: 1.2}` creates a new key; `- {append: components, value: {id: fin, type: tail_surface, ...}}` adds one element to a list that already exists (a list that does not exist yet, for example `mechanisms`, is created first with `- {add: mechanisms, value: [{id: ..., ...}]}`); `- {remove: "components[fin]"}` deletes one element. Quote any key that contains `[`. An agent without a Write tool makes the file with a shell heredoc (`cat > edits.yaml <<'EOF' ... EOF`).
- A motor component needs a `propulsion` block or the schema refuses it: `propulsion: {max_thrust_n: 12, axis: [-1, 0, 0], role: cruise, max_current_a: 18, prop_diameter_mm: 254}`. `axis` is the direction of the thrust force on the aircraft (`[-1, 0, 0]` for a forward-thrusting tractor or pusher; `[0, 0, 1]` for hover lift); `role` is `lift`, `cruise` or `both`; `max_current_a` and `prop_diameter_mm` are optional but the thrust and T7 checks use them. Take the numbers from the motor datasheet and note the source; a number that is only an estimate stays labelled as an estimate.
- Component types: there is no `control_surface` type. Ailerons and flaps are `wing`, elevator and rudder are `tail_surface`, servos are `servo`, horns, rods and pins are `other`.
```
