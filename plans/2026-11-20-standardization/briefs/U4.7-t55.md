What the diff does (the behaviour is fixed here; do not change it):
1. `design.set` gets two keyword-only string parameters `append` and `remove`. Because the CLI, MCP tools and Studio routes are generated from the op signature, all three get the flags with no further code. `docs/cli.md` is regenerated.
2. `--append X` adds one scalar entry at the end of the list at `key`; `--remove X` removes the first entry equal to X. X is read as one scalar by the existing `pdledit.parse_set_value` (so `2` is the number 2 and `'"2"'` is the text "2"; a mapping or list value is refused).
3. Only one-line flow lists `[a, b]` (including `[]`) are supported. A block list (`- a` lines) or a list that spans lines is refused with a message containing `one-line`; the file is not touched. Reason: pdledit already supports one-line flow values for add (`add_value`) and refuses block rewrites ("edit the file by hand"); a block-list edit would need new line-insertion logic and is not in D55.
4. Only the edited line changes. `append_item` inserts `, X` before the closing `]` (or `X` into `[]`). `remove_item` deletes the entry and one separator (the following one, or the preceding one for the last entry); every other entry on the line stays byte for byte as written (quotes and spacing). CRLF files stay CRLF. Both functions return `(patched text, old list, new list)`, verify that the result parses to the expected list, and that exactly one line differs; otherwise they raise `OpInputError` ("edit the file by hand").
5. The change goes through the same path as every `design.set` edit: schema check (a number in `authors` fails), one CHANGELOG.yaml entry with `kind: modify`, `old` and `new` holding the whole list, `--why` required.

Defaults taken (D55 leaves these open; all stated here, tested below):
- Value absent on `--remove`: error, exit code 2 (`data.error == "input"`, the existing input-error rule; D37 is about SKIP and does not apply), message contains `is not in the list`, nothing written.
- Key is not a list: exit 2, message contains `is not a list`. Key names a list element (`components[id]`, `x[0]`): exit 2, `name the list by its key`. Missing key: the existing `no key` error.
- Duplicates: `--remove` removes the first match only (the rest stay); `--append` does not check for an existing equal entry (a list may repeat a value).
- Match is by value and type: `1` does not match the text `"1"`, `true` does not match `1`.
- `--append`/`--remove` cannot be combined with each other, with `--value`, with `--also` or with a non-default `--kind`: exit 2. Blank value: exit 2, `non-empty`.
- Block-style lists: explicit error (item 3), not supported.
