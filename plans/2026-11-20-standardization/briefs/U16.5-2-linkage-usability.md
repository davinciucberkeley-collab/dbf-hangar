## Decisions (made here, do not revisit)
- (a) Report on a jam: yes. Today `follower_deg`, `deflection_deg` and `arm_length` are `None` whenever any input step jams, so the designer cannot see how far off the throw is.
- (c) Smaller of the two: `--dry-run`, not `--target-split`. Reason: a dry run is the same geometry and simulation code with the write and the 45 s validate skipped (it needs no new solver); `--target-split` needs a two-unknown search (arm offset and deflection) with its own convergence and failure modes and would still be a heuristic on top of a jam-prone four-bar. With `--dry-run` taking a few seconds the 3 to 5 trial runs per surface of the rehearsal cost seconds, not 45 s each. Not built here: `--target-split`.
- (d) Default `--servo-range 30` stays. Reason: D124 changed the default deflection, not the servo range; `servo_range` only sets the servo arm `range_deg` (the T1 sweep drives the servo through all of it, which is why 30 hit the fuselage and fin); changing the default rewrites every written servo-arm attachment of every re-run and the fixture hand values with no source for a better number. Fix by documentation: "set `--servo-range` to the input range plus 1 to 5 degrees; the rehearsal used 21 to 25 for input range 20".
- (b) Documentation only (table below).

## Code design (fixed)
1. New keyword `dry_run: bool = False` on `add_linkage_op` and `_add_linkage` (CLI flag `--dry-run`, registry name `dry_run`); op summary gets the sentence "`--dry-run` computes the geometry, ratio and throws and writes nothing (no CHANGELOG entry, no T0/T1 rows)."
2. Factor the block that reads the throws (current lines 358-372: `sim = simulate_mechanism(...)` through `min_mu`) into a local helper `_throws(design_like, mech, hinge_id, input_range)` returning `(follower, follower_input, deflection, min_mu, jam)`:
   - `steps = {s["input_deg"]: s for s in sim["steps"]}` (only inputs reached before a jam exist in `sim["steps"]`).
   - `follower["plus"]` = angle (rounded to 3, `+ 0.0`) at the largest reached input >= 0, `follower["minus"]` at the smallest reached input <= 0; `follower_input = {"plus": that input, "minus": that input}` as floats. Without a jam these are exactly `+input_range` and `-input_range`, so the existing values do not change. If no step at all was reached on a side, `follower = None` and `follower_input = None` (both sides).
   - `deflection` = mean of the two absolute angles rounded to 2, ONLY when there is no jam, else `None` (as today).
   - `jam = sim.get("jam")` (dict `{input_deg, reason}`) or `None`; `min_mu` as today.
   - `RuntimeError` from `simulate_mechanism` still gives `min_mu = None`, `follower = None`, `jam = None`.
3. `data_out` changes: `follower_deg` is now the dict above also on a jam (was `None`); `arm_length` is always `round(float(arm_length), 4)` (was `None` on a jam); new keys `follower_input_deg` (dict or None), `jam` (dict or None), `dry_run` (bool). Nothing else changes; the written `plane.yaml` for a run without jam is byte-identical to today.
4. First message line: when `jam`, append `, jam at input {input_deg:g} deg (follower_deg is the angle reached before it)` after the deflection and offset parts and before `; unchanged`.
5. Dry run: after `mech["expect"][0]["ratio"] = ratio` (line 279) and when `dry_run`, build `mem2` (copy of `mem` with the mechanism replaced by `copy.deepcopy(mech)`), call `_throws(Design(data=mem2, path=design.path), mech, raw_hinge_id, input_range)` and return at once: `OpResult(True, data_out, msgs, changed_files=[])` with `rows = []`, `changed = False`, `dry_run = True`, `kept_ratings = []`; no file read or written beyond what the function does today before line 280 (no `_write_with_log`, no `validate`). Message 1 is `dry run, nothing written: ` + the normal first line (without `; unchanged`). All input validation (`OpInputError` for `--arm-offset-deg`, `--deflection`, geometry) happens before, exactly as for a real run.
6. A real run (`dry_run=False`) after a dry run behaves as today.

## Docs text (`docs/mechanisms.md`, section "Generate the linkage")
Replace the sentence "`--servo-range` 30" in the "Other options" line by "`--servo-range` 30 (set it to the input range plus 1 to 5 degrees: the T1 sweep drives the servo through its whole range, so 30 can run the rod into the fuselage or fin; the rehearsal used 21 to 25 for input range 20)" and add `--dry-run` there ("computes and prints the throws without writing; 2 to 5 s, use it to tune `--arm-offset-deg` and `--deflection` before the real run"). Then add, after the "Read the two throws" paragraph, exactly this table (no figure) and the two sentences below it:

| Option | Positive / first value means | Negative / second value means | Notes |
|---|---|---|---|
| `--station S` (mm) | moves the linkage along the hinge attachment's `articulation.axis` as resolved (a `hinge_from: generator` hinge gives +y for wings and elevators, +z for rudders) | the opposite way along the axis | from the pivot; with a hand-typed axis `[0, -1, 0]` a negative station is toward +y |
| `--arm-side +` / `-` | `+`: the arm tip sits on the side of the shaft-to-pin line toward the right-hand rotation about the servo output axis | `-`: the other side | flipping it flips which end of the servo travel gives which surface direction, and which side of the horn the pin sits |
| `--arm-offset-deg A` | turns the arm tip toward the surface (horn direction) by A degrees at neutral | away from the surface | the throw that grows depends on arm side and servo orientation: on the test fixture (side +, axis `[0, -1, 0]`) +A shrinks the up throw faster than the down throw; on the c172 right aileron (side +) +22 gave up 19.4 / down 15.0 |
| `--horn-toward X,Y,Z` | the horn stands on the side of the plane (hinge axis, shaft) whose normal has a positive dot product with X,Y,Z | (the other side is never used) | the op stops when the dot product is below 0.3 in size: give a clearer direction |

"Positive follower angle is the right-hand rule on the hinge axis. If the wrong throw is the larger one, flip the sign of `--arm-offset-deg` (or `--arm-side`) and run with `--dry-run` to read the new pair from `follower_deg`. On a jam, `follower_deg` holds the angle at the last input reached on each side (`follower_input_deg` gives that input) and `jam` names the input that failed."
