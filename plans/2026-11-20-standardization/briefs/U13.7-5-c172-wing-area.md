## The numbers to explain (the conductor's side, 2026-11-25)
The C172 rehearsal design (`C:/Users/trist/wt/rehearsal2-c172/designs/c172-rc/plane.yaml`, draft PR #6; if that folder is gone use the parameters below) reports `T3.stall`: wing loading 56.3 g/dm2 at 889.5 g, i.e. a measured wing area of 889.53 / 56.25 dm2 = 15.81 dm2 = **158,130 mm2**. The hand value (rectangular 274 mm inboard, then taper 177 -> 116 mm to the tip, span 1200 mm, both sides) is `2 x (177 x 274 + (177+116)/2 x 326) = ` **192,514 mm2**. Difference -17.9 %.

## Hypothesis already worked out by hand (verify or refute it)
The wing component is `part: core` with `hinge_frac: 0.72` and two separate `part: elevon` aileron components (`elevon_y: [300, 540]`, `side: right` / `left`). The tier-3 measurement (`strip_planform` on `component + its articulated children`) therefore sees the core (0.72 of the chord everywhere) plus the aileron pieces over y 300..540 only. By hand: core = 0.72 x 192,514 = 138,610 mm2; ailerons add 2 x 0.28 x 149.6 x 240 = 20,102 mm2 (chord about 149.6 mm mean over y 300..540); sum = 158,712 mm2, within 0.4 % of the measured 158,130. If this holds, nothing is wrong with `strip_planform`, `inboard_span` or the airfoil scaling: the design simply leaves the trailing 28 % of the chord outside the ailerons (inboard flap area and the outboard tip) as no component, so tier 3 cannot count it. The brief's job is to prove or refute that with measurements, and to name the other candidates the ledger lists (strip measurement, `inboard_span`, airfoil scaling).

## Steps (measure; paste every number into the hand-back)
1. Build the wing three ways with `hangar.geom.registry.build_component` (base dir `tests/fixtures/pdl-gen` for the diamond airfoil, or `naca2412` after `import hangar.geom`), using these params for all: `{airfoil_file: naca2412, span: 1200, root_chord: 177, tip_chord: 116, inboard_span: 274, dihedral_deg: 1.6, placement: high, fuselage_height: 172, fuselage_center_z: 0}`: (a) `part: full`; (b) `part: core, hinge_frac: 0.72, elevon_y: [300, 540]`; (c) (b) plus the two `part: elevon, side: right/left` pieces with the same params.
2. For each of (a), (b), (c) measure the planform area with `hangar.geometry.strip_planform` exactly as `_tier3` calls it: `strip_planform({id: [meshes]}, "wing", n=<standards aero.planform_strip_count>, gap_tol=<geometry.strip_gap_tolerance_mm>, control_frac=<aero.control_surface_gap_max_fraction>)` (read the three values from `standards/design-standards.yaml`; paste them). Report `area_mm2`, `mac_mm`, `x_ac_mm`, `missing_stations`, `ignored_strips`.
3. Compare: (a) against 192,514 (expected within 1 %: this tests the strip measurement, `inboard_span` and the airfoil scaling in one go: the chord is measured along x of the section loop, the airfoil is normalised to chord 1); (b) against 0.72 x 192,514 = 138,610 (core only); (c) against 158,712 (core + ailerons) and against the 158,130 of the rehearsal.
4. Independent check of the analytic area: integrate the generator's own chord law numerically (`c(y) = root_chord` for `|y| <= inboard_span`, linear to `tip_chord` at `|y| = span/2`) with 10,000 steps and compare with 192,514 (guards the hand number).
5. Repeat step 2 (a) with `inboard_span: 0` and a single taper 177 -> 116 over the half span: hand area `2 x 600 x (177 + 116) / 2 = 175,800` mm2; report the measured value and its difference (guards `inboard_span` separately: the measured difference between (a) and this case should equal the hand difference 192,514 - 175,800 = 16,714 mm2 within 1 %).
6. Decision rule: if (a) is within 1 % of 192,514 and (c) within 1 % of 158,712, the verdict is "design modelling gap, not a bug": no code change; recommend to the conductor to add flap/trailing pieces or to build the wing as `part: full` plus separate aileron cut-outs (state which of `wing_panel`'s options exists today). If (a) is off by more than 1 %, find the cause (strip count, chord definition at the trailing edge, `z_offset`/placement shifting the section, airfoil trailing-edge thickness) with a minimal reproduction and write a failing test in `tests/test_wing_area_c172.py` that asserts the hand value within 1 %; only then change `core/hangar/geom/wing.py` or `core/hangar/geometry.py` (brief amendment needed: stop and report instead, listing the proposed change; do not edit code in this job).
