## Facts (W34-T5, main 7b5d764)
- `core/hangar/index.py:77-80` (`parts_json`) appends one row per visual node with `"type": v.kind` and `"visual_only": True`. `v.kind` is `"wire"` (visuals.py `_wires`), `"clevis"` (`_clevis_nodes`) or `"screw"` (`_screw_node`). Real components with `visual_only: true` in plane.yaml also get `visual_only: true` and keep their own component `type`.
- `viewer/ui/tree.js` has the two lines `const wiring = parts.parts.filter((p) => p.visual_only).map(row);` and `if (wiring.length) top.append(group('Wiring', wiring));`, which put every visual-only row under one group called Wiring. `group(name, items)` already exists in that function and sets `data-group=name` on the `li.part-group`.
- Decision: no `parts_json` change and no new field. The discriminator is the existing field `type` (`"clevis"`, `"screw"`); every other visual-only type (`"wire"`, a visual_only component) stays in Wiring as today.

def test_tree_groups_visual_nodes_by_kind(browser, pages_base):
    extra = [{"id": i, "type": t, "parent": None, "attachment": None, "depth": 0, "articulated": False,
              "position_mm": [0.0, 0.0, 0.0], "position_expr": False, "has_cavities": False,

## Code change (`viewer/ui/tree.js`)
Replace the two lines quoted above with:
```js
  const visual = parts.parts.filter((p) => p.visual_only);
  const kindGroup = { clevis: 'Clevises', screw: 'Screws' }; // every other visual-only type (wire, a visual_only component) stays in Wiring
  for (const name of ['Wiring', 'Clevises', 'Screws']) {
    const items = visual.filter((p) => (kindGroup[p.type] ?? 'Wiring') === name).map(row);
    if (items.length) top.append(group(name, items));
  }
```
