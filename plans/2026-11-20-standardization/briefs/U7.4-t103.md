## Decision: a `read` flag on PASS, not a new status
The smallest change that satisfies the ledger text is a boolean `read` next to the status, not a fifth status `READ`. Reasons, checked against the code:
- A new status `READ` would touch `ClaimResult.status` (`core/hangar/claims/graph.py` `Literal`), `schema/claims.schema.json` (if status is enumerated there), the T9 map `_MAP` in `core/hangar/gates/claims.py` (PROPOSED to SKIP, STALE to WARN, so READ needs a mapping: PASS would keep it quiet, SKIP would put 40 rows into the baseline), `ops/claims.py` counts and every consumer that tests `status == "PASS"`: `graph.py` line 210 (`recomputed = ... res.status in ("PASS", "FAIL", "STALE")`, which decides whether a claim result can feed another claim) would silently change for any claim that consumes a read claim. That is a behaviour change with a baseline and test fallout, for no extra information.
- With the flag, statuses, T9 statuses, `plane baseline check --all` and every existing test are unchanged (verified: baseline `Regressions: 0`, concept-a `Known results: 83 (FAIL 10, SKIP 73). Unchanged: 83`).
- The marker is derived, not authored: it comes from the calc function. `read_value` is marked with the attribute `stored_result = True`; any later stored-result function gets the same attribute. No `claims.yaml` field and no schema change.

What the diff does (behaviour fixed here):
1. `core/hangar/calcs/__init__.py`: `read_value.stored_result = True`.
2. `core/hangar/claims/graph.py`: `ClaimResult` gets a last field `read: bool = False`; `_evaluate` sets it when the claim's calc function has `stored_result` (an unregistered function gives `False`); a PASS message of a read claim starts `stored result read from source, not recomputed; ` (then `margin ...` or `no limit`).
3. `core/hangar/gates/claims.py`: every T9 row's `data` gets `"read": r.read`.
4. `core/hangar/ops/claims.py`: `claim.list` and `claim.check` rows get `"read"`; `claim.list` data gets `"read_count"`; the plain-text list shows `PASS (read)` in the status column (column width grows only when a read row exists); `claim.check` adds one message line `note: N PASS recomputed, M PASS read from source (stored results checked against their limits, analyses not re-run)` when M > 0 (on concept-a: `note: 53 PASS recomputed, 40 PASS read from source ...`, matching the D60 wording).
5. Test texts named by W13-R: the comment on `tests/test_calcs_concept_a.py::test_concept_a_t9_has_no_skipped_claim_and_no_fail` no longer says "recompute (from live PDL values)"; `tests/test_import_dbf_v2.py` test `..._recomputes_all_93_read_value_echoes_included` is renamed `test_concept_a_claims_import_evaluates_all_93_claims_read_value_echoes_included` (nothing else references the old name; the two older briefs and the review file that quote it are history and stay).
