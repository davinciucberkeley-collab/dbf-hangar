```python
@dataclass(frozen=True)
class Gate:
    id: str; tier: int; name: str; fn: Callable[["GateContext"], "TierReport | None"]; needs_mass: bool

@dataclass
class GateContext:
    design: Design; std: dict; mp: dict | None; today: datetime.date

def gate(id: str, tier: int, *, needs_mass: bool = False): ...   # decorator; registers fn in GATES[id]; raises ValueError on a duplicate id or duplicate tier; returns fn unchanged
GATES: dict[str, Gate]
def load_gate_table() -> list[dict]        # rows of standards/gates.yaml in file order, fresh copies
def run_gates(design: Design, max_tier: int = 9, *, strict: bool = False,
              only_tiers: "set[int] | None" = None, today: "datetime.date | None" = None) -> Scorecard
```
`run_gates` behaviour (this is the whole algorithm; it reproduces today's `validate`):
1. Import the registering modules lazily: `from .. import checks`, and `from . import mechanisms, integration, sourcing, claims` (the last four register their gate when imported; `checks` registers tiers 0 to 5).
2. Run the tier 0 gate **unwrapped** (an exception propagates, as today). Always run it, even when `only_tiers` excludes tier 0. If its report status is FAIL, return the scorecard with just that tier.
3. For each other gate with `tier <= max_tier` in tier order (skipping tiers not in `only_tiers` when given): if `needs_mass` and `ctx.mp` is not computed yet, compute `mass_properties(design)` once; if it raises, add a `T{t}.blocked` FAIL row (message `f"mass properties failed: {e}"`, criterion = the gate-table criterion) for **every** `needs_mass` gate with `tier <= max_tier` that has not run yet, as tier reports with each gate's name, and return at once (T6 to T9 do not run after a mass failure, as T9 did not before). Otherwise run `fn(ctx)` inside try/except: a crash becomes `TierReport(tier, name, [CheckResult(f"T{tier}.error", FAIL, f"{type(e).__name__}: {e}", <gate-table criterion>)])`. A `None` return adds no tier.
4. Report-only: for a gate whose table `blocking` is `false`, and `strict` is false, rewrite every result with status FAIL or SKIP to status WARN, message prefixed `report-only until 2026-12-08: `, and `data["report_only"] = True` and `data["raw_status"] = <old status>`. With `strict=True` nothing is rewritten.
5. Return `Scorecard(design.id, tiers, max_tier, fidelity=compute_fidelity(design, tiers))` (step 9).
`today` defaults to `datetime.date.today()`.

  - Interference: for every `mechanism_contact_step_deg` of driver input (always including the last step), pose the design with `posed_component_parts(design, {driver_label: inp, <follower label>: its simulated angle, ...})`; for every pair (moved component, other component) where at least one component is in `downstream_ids` of the driver or of a follower, the two components are NOT joined by an attachment, and neither is a `propeller`: if `checks._overlap_volume(parts_a, parts_b) > interference_max_mm3` then FAIL `f"mechanism {id}: {a} and {b} collide at input {inp:.0f} deg ({vol:.1f} mm3 > {limit} mm3)"`, `data` adds `"pair": [a, b]`. Pairs already overlapping at input 0 by more than the limit are ignored (T1 reports them).
  - All good: PASS `f"mechanism {id}: {n} follower(s) track ratio x input over {lo:.0f} to {hi:.0f} deg"`.
- `simulate_mechanism(design, mech) -> dict` (public, also used by the op): returns `{"mechanism": id, "driver": label, "steps": [{"input_deg": float, "followers": {attachment label: angle in degrees}}, ...]}`. A non-articulated attachment joins the child body to its parent with no joint (rigid). An articulated attachment gives the child body a `<joint type="hinge" pos=<pivot mm to m> axis=<axis> range=<range_deg> limited="true" damping="0.05"/>` named after the attachment label. Add one `<position>` actuator on the driver joint (`kp="200"`, `ctrllimited` off) and, for every `expect` row, `<equality><joint joint1=<follower joint> joint2=<driver joint> polycoef="0 <ratio> 0 0 0"/>` (the follower tracks ratio x driver).
