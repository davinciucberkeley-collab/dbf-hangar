# Brief U13.7-2-verdict-date: the design-verdict test uses a pinned date (T134)

class: easy · role: builder · plan: §7 U13.7 (T134; W29-R note on U12.1-2) · depends on: nothing · merge order: 2nd · SLUG = `verdict-date`

Environment: follow `plans/2026-11-20-standardization/briefs/U13.7-env.md` with SLUG=verdict-date (Haiku trailer).

## Why
`tests/test_applicability.py::test_design_verdicts_unchanged_against_main` calls `validate(load_design(...))`, and `validate` runs the gates with `today=datetime.date.today()` (`core/hangar/gates/__init__.py` line 131), which the T8 sourcing check uses for the 30-day BOM staleness. The expected tiers in `tests/fixtures/design-verdicts.json` were recorded on 2026-11-24, so the test's outcome depends on the day it runs (BOM lines verified 2026-11-14 turn stale on 2026-12-14). Checked 2026-11-25 on `c0-lift-cruise`: the tier verdicts are the same at 2026-11-24 and 2026-12-20 today (T8 is WARN either way while report-only), so the drift is latent, not visible yet: this brief removes the dependency, not a failing test. The report-only flip on 2026-12-08 is a standards change (`blocking` true in `standards/gates.yaml`), after which the fixture must be regenerated by hand: this brief documents how.

## Where
Branch `std/u13.7-verdict-date`. Files you may change: `tests/test_applicability.py` (only that one test), `tests/fixtures/design-verdicts.json` (one new key). Nothing else.

## Exact steps
1. `tests/fixtures/design-verdicts.json`: add a top-level key `"_recorded"` with the value `{"today": "2026-11-24", "how": "run_gates(load_design(designs/<id>), 9, today=<today>) on origin/main; regenerate with the snippet in tests/test_applicability.py after the 2026-12-08 report-only flip"}`; keep every other key and value byte-for-byte (edit by inserting the new key as the first member; keep the file's indentation style).
2. `test_design_verdicts_unchanged_against_main`: read `want = json.loads(...)`; `rec = want.pop("_recorded")`; `today = datetime.date.fromisoformat(rec["today"])`; use `from hangar.gates import run_gates` and `sc = run_gates(load_design(DESIGNS_DIR / name), 9, today=today)` instead of `validate(...)`; assertions unchanged. Put this docstring on the test, exactly: `"""Verdicts are recorded for a pinned date (fixture key _recorded). To regenerate after a standards flip: for each design id in the fixture, run_gates(load_design(DESIGNS_DIR / id), 9, today=<recorded date>) and write {"accepted": sc.accepted, "tiers": {str(t.tier): t.status for t in sc.tiers}}; review the diff by hand."""`
3. Add one new test below it, `test_verdict_fixture_records_its_date`: `rec = json.loads(...)["_recorded"]`; `datetime.date.fromisoformat(rec["today"])` parses; the set of other keys equals `{p.name for p in DESIGNS_DIR.iterdir() if (p / "plane.yaml").is_file()}` (a new design must be added to the fixture or this fails: that is intended).
