What the diff does (the behaviour is fixed here; do not change it):

**T91: redirect.** `design.py` gets `DESIGNS_DIR_ENV = "PLANE_DESIGNS_DIR"`; `DESIGNS_DIR` is that folder when the variable is set and non-empty, else `REPO_ROOT / "designs"` as before. `run_op` sets it to `<ws>/designs` in the agent's environment, and `replay` sets it to `<replay>/designs` for each replayed command. So `design new`, `design copy` and the old `plane new` create their folder in the workspace (and its replay) instead of the real repo. Why an env variable read by `design.py`, and not the alternatives: (a) redirecting `REPO_ROOT` would also move `SCHEMA_PATH`, `standards/*.yaml`, `gates` and `knowledge/` into the workspace, which has none of them, so every validation would break; (b) patching `DESIGNS_DIR` from `bench.py` only works in the grader's own process, not in the `plane` processes the agent starts; (c) the same mechanism as `PLANE_BENCH_LOG` (T54): inert when unset, the agent cannot unset it because only `plane *` commands are allowed, tested with real child processes. The variable is read once at import time, which is right because every `plane` command is a new process. `SWEEP_ROOT` (`design.sweep` scratch copies under the real repo's `.sweeps`) is not redirected: that op is read-only (`mutates=False`) and its scratch folder is deleted and rebuilt on every call; left to the conductor.

**T92: pin the snapshot.** `bench.tree_digest(root)` is a sha256 over every file's relative path and content. `run_op` computes it right after `snapshot_design` and keeps it in memory (a variable, never written to disk, so no command can touch it); `grade(..., digest)` hands it to `replay(..., digest)`, which returns `the pre-run snapshot changed during the run; cannot replay` before anything runs when the tree no longer matches. Why a digest and not a separate `mkdtemp`: a separate folder only hides the path, and the agent has Glob and Read across the file system, so it could still find it; the digest detects the change however the path was reached. The `snapshot_design` docstring no longer claims the agent "cannot reach" it.

**T92: allow-list.** `bench.replay_kind(argv)` returns one of three:
- `skip` (not run, not a difference): no words or an option first (`--version`); the old read-only commands `validate`, `mass`, `list`; a registered op with `mutates=False` (`design mass`, `design get`, `fea plan`, ...); a registered group with a missing or unknown verb (`plane design`, `plane design bogus`: click only prints help or a usage error), except where the old command runs, which is the `fea` group (`plane fea PATH --all` runs OpenCAE), so that one is `refuse`.
- `replay`: `REPLAY_ALLOW = design set, design copy, design new, new`. Why these four: they are the only commands that change files under `designs/` and that write only below the design folder they are given (`set`, `copy`) or below `DESIGNS_DIR` (`new`, `design new`, now inside the workspace). Everything the three bench tasks need is `design set`.
- `refuse`: everything else, including `bench run` (would start another paid `claude` run), `fea run` (600 s timeout, writes under the real repo), `design export` and `assembly animate` (write to any `--out` path), `design propose` (git and a PR), `ledger`, `update`, `idea`, `bom verify`, `morph`, `import`, `baseline update`, `studio`, and an unknown command. A refused command fails the run with one message `` `plane <argv>` is not a command a bench run may use (allowed: ...); not replayed `` and nothing is started: `replay` checks every logged command first and only then creates the replay folder and runs anything.
Existing behaviour that changes: before, an unknown or non-allow-listed mutating command was replayed (fail closed by running it); now it fails the run without running (fail closed by refusing). `replayable()` is removed (one caller, one test), replaced by `replay_kind`.

**T92: paths outside the workspace.** `_map_args(argv, cwd, ws, fresh)`: every argument that is not an option and that names an existing path (resolved against the logged cwd) is mapped to the same relative path inside the replay folder when it resolves inside the workspace, and is a failure message `` ... names a path outside the workspace: <arg> `` when it does not (the snapshot, the real repo, the temp folder). A logged cwd outside the workspace is also a failure. Arguments that are not existing paths (keys, `--why` text, numbers, ids) are kept as they are.

**T93: path mapping.** Because `_map_args` compares resolved paths, the old string replace in `replay` (8.3 short names, different case, `../<run_id>/designs/...` all missed it, so the replay wrote into the graded workspace) is gone; a test runs a real `design set ../<run_id>/designs/concept-a ...` and checks the replay leaves the workspace byte for byte unchanged.

**T93: unwritable log.** `cli._log_invocation` catches `OSError` when opening or writing `PLANE_BENCH_LOG`, prints `plane: cannot write PLANE_BENCH_LOG <path>: <reason>` (one line, stderr) and exits 2, so the command does not run unlogged; no traceback.
