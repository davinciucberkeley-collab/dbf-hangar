How the headless agent calls `plane` (read from `run_op`): `claude -p ... --allowedTools "Bash(plane *),Read,Grep,Glob"` is started with `cwd` = a scratch workspace and `PATH` = the folder of `sys.executable` first. The agent has no Write or Edit tool; its only way to change files is a `Bash(plane *)` command, and a command that does not start with `plane ` is not allowed. `plane` is the console script `hangar.cli:main`.

Logging mechanism chosen: `main()` appends one JSON line `{"argv": [...], "cwd": "..."}` to the file named by the environment variable `PLANE_BENCH_LOG` before it runs the command, and does nothing when the variable is unset. `run_op` sets the variable (agent environment only) to a file outside the workspace. Why this and not the alternatives:
- A PATH shim (a `plane` wrapper script or `plane.cmd` in the workspace) needs one script per OS, quoting of argv in sh/cmd, and a way to find the real `plane`; it cannot be tested without running a shell wrapper on both CI systems.
- Logging in the op layer (`ops._call_spec`) misses the commands that are not ops (the old commands such as `plane new`), so a legitimate agent command would be absent from the replay and fail the run.
- The `main()` hook sees every `plane` invocation with its exact argv on every OS, is 8 lines, is inert without the variable, and is tested by calling `main()` directly. The agent cannot unset it: `VAR= plane ...` does not start with `plane ` and is not allowed.

What the diff does:
1. `core/hangar/cli.py`: `BENCH_LOG_ENV = "PLANE_BENCH_LOG"`, `_log_invocation()`, and `main()` calls it first.
2. `bench.snapshot_design(task, ws)` copies the prepared workspace design to `<ws parent>/snapshot/designs/<name>` (outside the workspace) and returns `<ws parent>/snapshot`.
3. `bench.replayable(argv)`: False only when the first two words are a registered op with `mutates=False` (for example `design mass`, `design get`); everything else, including unknown commands, is replayed.
4. `bench.designs_diff(a, b)`: relative paths that exist on one side only or differ. Compared byte for byte, except `CHANGELOG.yaml` is compared as parsed entries without each entry's `date` (design.set stamps the time, so a replay can never match the date), and the folders `fea`, `.sweeps`, `__pycache__` are not compared (`prepare_workspace` does not copy them either).
5. `bench.replay(ws, snapshot, log)`: builds `<ws parent>/replay` (copy of the snapshot plus an empty `pyproject.toml` so the ops find a repo root), runs each replayable logged command in order as `python -m hangar.cli <argv>` with `PLANE_BENCH_LOG` removed from the environment, `cwd` mapped from the logged cwd into the replay folder, and every occurrence of the workspace path in argv replaced by the replay path (both slash styles). It ignores exit codes. It returns `[]` or one message `designs/ differs from a replay of the logged plane commands: <paths>`; an unreadable log gives `the plane command log is unreadable; cannot replay`; a replay command that times out (600 s) gives a message too. A missing log file means the agent ran no `plane` command: nothing is replayed, so any change to `designs/` is a difference.
6. `bench.grade(task, ws, repo, snapshot=None, log=None)`: with a snapshot, the replay messages are added to `messages`; the existing rule then gives `passed=False`, `score=0.0`. Without a snapshot nothing changes, so the existing grader tests stay as they are.
7. `run_op` takes the snapshot right after `prepare_workspace`, sets `PLANE_BENCH_LOG` to `<ws parent>/plane-commands.jsonl` in the agent's environment, and passes both to `grade`. The record JSON already stores `messages`, so a failed replay shows in `bench/results/runs/*.json`.

Defaults taken (D56 leaves these open; all stated here, tested below):
- Read-only commands are skipped in the replay but are still logged. Unknown commands are replayed (fail closed).
- Replay is deterministic for `design set` and other commands that write only from their arguments and the design files. A command that writes a clock value other than `CHANGELOG.yaml` `date` would make the replay differ and fail the run; that is the safe direction and is left to a later item if it ever happens.
- Exit codes of replayed commands are ignored (a command that failed for the agent failed the same way, with the same effect, which is none for the atomic ops).
- `fea/`, `.sweeps/`, `__pycache__/` are not compared.
- Not covered here (report to the conductor, do not fix): ops that write under `design.DESIGNS_DIR` (set from the installed package location, not the workspace; for example `design new`) write to the real repo in the agent run and again in the replay; they are outside `ws/designs`, so this check does not see them. Edits to files outside `designs/` are not checked by this brief (core, schema and standards stay protected by the fingerprint).
- `bench.run` is the only caller that passes a snapshot; `bench.grade` called directly (as the existing tests do) does not replay.
- `tests/test_bench.py::test_every_bench_write_text_call_passes_newline_lf` counts exactly 4 `write_text` calls in `bench.py`; the diff adds none (it uses `write_bytes` and `open(..., newline="\n")`), so the count stays 4.
