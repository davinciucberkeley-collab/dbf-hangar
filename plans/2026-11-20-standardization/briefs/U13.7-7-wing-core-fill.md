# Brief U13.7-7-wing-core-fill: opt-in `core_fill` so a core plus elevon wing has no uncovered trailing edge (T145)

class: hard · role: builder-plus · plan: §7 U13.7 (T145; evidence `plans/2026-11-20-standardization/u13.7/c172-wing-area-findings.md`) · depends on: U12.3 / U13.3-4b (merged: `wing_panel` parts, `inboard_span`) · merge order: any · SLUG = `wing-core-fill`

Environment: follow `plans/2026-11-20-standardization/briefs/U13.7-env.md` with SLUG=wing-core-fill.

## Why (measured, T143 findings)
A wing built as `part: core` (leading edge to `hinge_frac`) plus `part: elevon` pieces over `elevon_y` only leaves the trailing `1 - hinge_frac` of the chord outside `elevon_y` belonging to no component. C172 rehearsal: full wing 192,517 mm2 measured (hand 192,514); core 138,612 (hand 138,610); core + two ailerons 158,131 = the rehearsal's 158,130, i.e. -18 % wing area, so stall speed and wing loading were wrong. Fix, opt-in: `core_fill: outside` makes the core full-chord outside the `elevon_y` span, so core plus elevon pieces cover the whole planform. Default `off` keeps every current result bit-identical.

## Exact steps
1. New param on `wing_panel`, after `elevon_y`: `"core_fill": ParamSpec("choice", default="off", choices=("off", "outside"), doc="part core only: outside = full chord outside the elevon_y span, so the elevon pieces over elevon_y complete the wing; off = core to hinge_frac everywhere")`.
2. `_build`, only when `part == "core"` and `core_fill == "outside"` (any other combination: no change at all): after `core = _loft(unit, p, ys)` and before the `bore_d` block, build the full-chord pieces and unite them with the core: `y0, y1 = p["elevon_y"]`; `full_unit = _unit_loop(upper, lower, 0.0, 1.0)`; for each side sign `s` in `([1, -1] if side == 0 else [side])` and each `(a, b)` in `[(0.0, y0), (y1, half)]` with `b - a > 1e-9`: stations `[s * a, s * b]` plus `s * ib` when `a < ib < b` (as the elevon branch does), `fills.append(_loft(full_unit, p, stations))`; then `core = kernel.union([core] + fills)` when `fills` is non-empty. Bore and cut handling below stay as they are and act on the united core. Return `[core]` as now (one part).
3. `_check`: add `"core_fill: outside needs part core and elevon_y with 0 <= y0 < y1 <= span/2"` when `core_fill == "outside"` and (`part != "core"` or not `0 <= y0 < y1 <= span / 2`). (When `elevon_y` is the default `[0, 0]` this fires: that is intended.)
4. `docs/mechanisms.md`: append a section `## Splitting a wing into core and ailerons` of about 12 lines: the three-piece layout (wing `part: core`, two `part: elevon` pieces with `side: right` / `side: left`, same params and `elevon_y`); the pitfall with the C172 numbers (core to 0.72 chord leaves 28 % of the chord outside `elevon_y`: area 158,130 instead of 192,514 mm2); the fix `core_fill: outside` on the CORE component only (not on the elevon pieces) so the area is complete again (192,517 mm2 measured); and the reminder that the pieces must stay `articulated` children of the wing for `T3` to count the aileron area (the planform is measured from the core and its articulated children).
