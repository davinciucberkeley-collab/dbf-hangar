## Exact steps and outputs
### 1. `viewer/vp/measure.js`
Exports `class Measure { constructor(vp) }` with: `click(hit)` where `hit = { point: THREE.Vector3 (scene m), face, object } | null`: first click stores point A and draws a marker; second click stores B, draws the line and shows the label; a third click clears and stores a new A; `null` does nothing. `clear()` removes markers, line and label. `result()` returns `null` or `{ a_mm: [x,y,z], b_mm: [x,y,z], distance_mm }` (body mm through `sceneToMm` from `vp/transforms.js` for the points, `distance_mm = round(|A - B| in scene metres * 1000, 1)`). Visuals (all under `vp.root`, disposed by `clear()` and `dispose()`): two small spheres (radius = model diagonal * 0.006, colour `0xf97316`, `depthTest false`, `renderOrder 10`), one `THREE.Line` between them (`depthTest false`, same colour), and a DOM label `<div class="measure-label" data-testid="measure-label">` appended to `.vp-wrap`, positioned each frame at the projected midpoint (hidden when behind the camera), text `fmt(distance_mm, 1) + ' mm'` and, in smaller type, `dx dy dz` body-mm components (`Δx 300.0 Δy 0.0 Δz 0.0`). `vp.tick()` (B0) calls `measure.update()` to place the label when `measure.result()` is set (request a frame while the camera moves: `controls` 'change' already sets `dirty`).

### 2. Tool, snap and hooks (`scene.js`, `app.js`, `index.html`)
- Button `[data-testid="tool-measure"]` (label `Measure`) added to `#tool-bar` after `tool-move`; key `d` toggles it (ignored inside inputs). With the tool active the canvas cursor is `crosshair`, picking parts is off (plain clicks do not select), the gizmo (B5) is hidden. `Escape` clears the measurement first, then (second press) returns to Select.
- A canvas click with the Measure tool: ray as in B2/B3 (`hitsAlong`, first pickable hit: ghosted, hidden and clipped-away parts are skipped), then snap: of the three vertices of the hit triangle (`face.a, b, c` of the hit geometry, transformed by the object's `matrixWorld`) take the nearest to the hit point; if that distance is below `snapRadius` use it, else keep the exact hit point. `snapRadius` for real clicks = the world-space size of 8 screen pixels at the hit distance (`2 * distance * tan(fov / 2) / canvasHeightPx * 8`).
- Hooks: `vp.measureClick(originMm, dirMm, snapMm = 0)` does exactly the click logic for a ray given in body mm (origin and direction converted like `pickRay` in B3, `snapRadius = snapMm / 1000`), switches the tool to Measure if needed, feeds `Measure.click`, and returns the clicked point as body mm `[x, y, z]` (rounded 0.1) or `null` when the ray hits nothing pickable. `vp.measurement()` returns `Measure.result()`. `vp.clearMeasure()` clears. `state()` gains `measure: <result or null>`.
- Changing explode (`vp.explode`, B4), the section plane (`vp.section`, B3), the design (`show()`), or pressing Revert/Apply (B5) calls `clearMeasure()`.

### 3. View cube (`viewer/ui/viewcube.js`, `index.html`, `style.css`)
- Markup in `.vp-wrap` (top-right, 72 px): `<div id="view-cube" class="view-cube" data-testid="view-cube"><div class="cube-inner" id="view-cube-inner">` with six faces `<button class="cube-face" data-testid="cube-front|cube-back|cube-top|cube-bottom|cube-left|cube-right">` labelled `Front`, `Back`, `Top`, `Bottom`, `Left`, `Right`. Each face positioned with `transform: rotateX/rotateY(...) translateZ(36px)` in the usual CSS cube arrangement; `.cube-inner { transform-style: preserve-3d }`; no CSS `perspective` on `#view-cube` (orthographic cube, so an edge-on face has near-zero area).
- Naming (body frame, scene axes in B2): Front = looking from the nose side (camera on scene +x), Back = scene -x, Top = camera above (scene +y), Bottom = below, Left = camera on scene +z, Right = camera on scene -z. Clicking a face calls `vp.view(name)` (B2's `view()` gains `bottom`: direction `(0,-1,0)`, `camera.up = (1,0,0)`; `left`: direction `(0,0,1)` (same as `side`); `right`: `(0,0,-1)`).
- `export function updateCube(camera, inner)`: sets `inner.style.transform` to the inverse of the camera's rotation so the cube turns with the model: take `e = camera.matrixWorldInverse.elements` (call `camera.updateMatrixWorld()` and make sure `matrixWorldInverse` is current) and apply `matrix3d(e0, -e1, e2, 0, -e4, e5, -e6, 0, e8, -e9, e10, 0, 0, 0, 0, 1)` (CSS y points down; if the faces do not match the check in the tests below, fix the sign pattern until they do and note the final pattern in a code comment: the tests decide, not this formula). Called from the controls `change` handler and once after `show()`/`view()`.
