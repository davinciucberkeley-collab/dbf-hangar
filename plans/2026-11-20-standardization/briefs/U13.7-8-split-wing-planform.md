## Finding (investigated 2026-11-25 on main; it is NOT a separate-surfaces bug)
Rehearsal 3 reported "split wing pieces counted as separate lifting surfaces: NP 806 -> 829 mm, MAC 228 -> 173 mm". The design (`C:/Users/trist/wt/rehearsal3-a400m/designs/a400m-rc`) has ONE core component `wing` (`wing_panel`, `part: core`, default `hinge_frac` 0.7, `elevon_y [560, 800]`), and two aileron components (`part: elevon`, `side: right/left`) joined by articulated hinge attachments (`r-hinge`, `l-hinge`). `generated_planform` returns `None` for the elevon pieces, so they never count as surfaces: the wing is one measured surface (`strip_planform` on the core and its articulated children). Measured with exactly that call on the design's parameters (`.logs` script, standards values 41 strips, 3.0 mm, 0.15): unsplit `part: full`: area 349,489 mm2, MAC 226.4 mm, x_ac 697.4 mm; split core + two ailerons: area 279,206 mm2 (-20.1 %), MAC 174.4 mm, x_ac 691.3 mm. The cause is the one of T145: the core stops at `hinge_frac` of the chord everywhere, the ailerons cover only `elevon_y`, so the trailing 30 % of the chord outside `elevon_y` belongs to no component; the shorter chords lower MAC, shift x_ac and so the neutral point and the static margin (23-32 % MAC instead of about 7.5 % by hand). The geometry fix is `core_fill: outside` (U13.7-7). This brief adds the missing visibility: nothing in tier 3 tells the designer that the measured wing is incomplete.

## Rule
For each component the derived path measures (`generated_planform(c)` returns `{"measured": True}`) whose generator params have `part == "core"` (a plain `part: full` wing is always complete and gets no row; a wing with a declared `planform` or a `lifting_surface` never reaches this path, so concept-a and concept-a-param get no row): compare the measured `area_mm2` with the area the params give, `analytic_wing_area(c) = 2 x (root_chord x ib + (root_chord + tip_chord)/2 x (span/2 - ib))` with `ib = inboard_span` (default 0), and emit one row `CheckResult("T3.wing_area_complete", status, message, "gate-thresholds.yaml#wing_area_complete_min", {"component": id, "measured_mm2": round(m, 1), "analytic_mm2": round(a, 1), "ratio": round(m / a, 4)})`: PASS when `m / a >= wing_area_complete_min` with message `f"{id}: planform complete ({m / a:.1%} of the {a:.0f} mm2 the wing_panel params give)"`; WARN otherwise with message `f"{id}: measured planform {m:.0f} mm2 is only {m / a:.1%} of the {a:.0f} mm2 the wing_panel params give; the chord behind hinge_frac outside the control surfaces belongs to no component (set core_fill: outside on the core, or add trailing pieces); wing area, MAC and the neutral point are off"`. The row is added to the tier-3 results next to the planform rows (it needs no effect on stall or static margin numbers).

## Exact steps
1. `planform.py`: `def analytic_wing_area(component: dict) -> float | None`: same defaults filling and `try/except -> None` as `generated_planform`; returns the formula above for a `wing_panel` component of type `wing` with `side == "both"` and `part == "core"`, else `None`.
2. `standards/gate-thresholds.yaml`: append `wing_area_complete_min: {value: 0.97, rule: "T3.wing_area_complete: the measured planform area of a generated core wing divided by the area its wing_panel params give must be at least this; below it the wing has uncovered chord (a WARN).", source: pending, note: "Strip measurement agrees with the params within 0.1 % on a complete wing (U13.7-5 findings); 0.97 leaves room for sweep and airfoil tip effects; internal expectation, no external source."}` written in the layout of the neighbouring entries (block style with `value`, `rule`, `source`, `note` keys).
3. `checks.py` `_tier3`: where the derived loop computes `p = strip_planform(...)` for a `measured` component, if `c["geometry"]["params"].get("part") == "core"` (use the defaults-filled params via `analytic_wing_area(c) is not None`), remember `(c["id"], p["area_mm2"], analytic)`; after the surface loop append one row per remembered wing as specified (threshold read with `load_gate_thresholds()["wing_area_complete_min"]["value"]` as `mechanisms.py` reads its thresholds, or `resolve_threshold`). No other change in `_tier3`; static margin, stall and the existing `surfaces` data are untouched.
4. `docs/mechanisms.md`: add one sentence at the end of the section `## Splitting a wing into core and ailerons`: `Tier 3 warns with T3.wing_area_complete when the measured wing is less than 97 % of the area its wing_panel params give.` (If that section is missing because U13.7-7 is not merged, stop.)
