### C1. Sharding (diff verified: collect-only, the 3 shards' union equals the full set, 968 nodeids, no overlap)

`tests/conftest.py`: append at the end of the file:

```python
def pytest_addoption(parser):
    parser.addoption("--shard", default=None, help="run one slice of the collected tests, as I/N (1-based); CI splits the unit tests across N jobs")


def pytest_collection_modifyitems(config, items):
    spec = config.getoption("--shard")
    if not spec:
        return
    index, count = (int(x) for x in spec.split("/"))
    assert 1 <= index <= count, f"--shard {spec}: need 1 <= I <= N"
    ordered = sorted(items, key=lambda it: it.nodeid)
    mine = {it.nodeid for k, it in enumerate(ordered) if k % count == index - 1}
    dropped = [it for it in items if it.nodeid not in mine]
    config.hook.pytest_deselected(items=dropped)
    items[:] = [it for it in items if it.nodeid in mine]
```

Balance: plain round-robin on sorted node ids was measured to be uneven (shard 1 got test_fea_plan_op, test_plane_fea_group, both fix-static-margin bench tests and test_missing_tool; shard 3 got 4 of the 6 concept-a-parametrised ids). So add, before `ordered = ...`, a HEAVY list dealt first: define at module level

```python

    "tests/test_pdl.py::test_every_committed_design_migrates_to_1_1_with_same_verdict[concept-a]",
    "tests/test_gates.py::test_program_constraints_apply_to_every_active_design[concept-a]",
    "tests/test_gates.py::test_tiers_0_5_unchanged_for_committed_designs[concept-a]",

    "tests/test_fea.py::test_hub_is_held_by_bridge_and_struts_not_by_wiring",
```

### C2. concept-a geometry memo (UNVERIFIED as a diff; mechanism verified: a wrapper patched onto `hangar.checks.tier1_geometry` is called by `_gate_t1`, `core/hangar/checks.py:1066`, and that is the only caller)

`tests/conftest.py`: add imports `copy, hashlib, json`, `import hangar.checks as _checks`, `from hangar.design import DESIGNS_DIR`, and this fixture:

```python
_T1_MEMO: dict[str, object] = {}


@pytest.fixture(scope="session", autouse=True)
def _share_concept_a_geometry():
    """Tier-1 geometry of the committed concept-a costs 28 to 54 s and nine tests ask for it: compute it once per
    worker. Only the committed folder is shared (same data, same standards), and each caller gets its own copy."""
    real = _checks.tier1_geometry

    def memo(design, std):
        if design.base_dir != DESIGNS_DIR / "concept-a":
            return real(design, std)
        key = hashlib.sha256(json.dumps([design.data, std], sort_keys=True, default=str).encode()).hexdigest()
        if key not in _T1_MEMO:
            _T1_MEMO[key] = real(design, std)
        return copy.deepcopy(_T1_MEMO[key])

    mp = pytest.MonkeyPatch()
    mp.setattr(_checks, "tier1_geometry", memo)
    yield
    mp.undo()
```

Reasoning to keep in a one-line comment, not more: tests that change geometry work on `tmp_path` copies or on mutated `design.data` (different key), so they never hit another test's entry. If any test fails only with the memo (run once with and once without), stop and report which test; do not widen or narrow the rule to make it pass.

### C6. `_min_distance` early exit (diff verified for exactness of the output type and for the call-count drop; not verified over the full suite)

`core/hangar/checks.py`: `_min_distance(a, b, stop_at: float = -1.0)`: after each of the two `signed_distance` calls in the inner loop, `if best <= stop_at: return best` (compute the `pb`-against-`pts_a` call first, test, then the `pa`-against-`pts_b` call, test). `_PairCache.gap(self, meshes, tf, a, b, stop_at=-1.0)` passes `stop_at` through; the only caller (`checks.py:393`) becomes `cache.gap(meshes, tf, p, c, tol)`. Why this changes no result: the only use of the gap is `if d > tol` and the message printed only when `d > tol` (`checks.py:393-398`); a pair whose gap is already `<= tol` can never reach the message, and the cache is per configuration with a fixed `tol`. Do not add a bounding-box prune: it was tried (box gap against the running best) and changed nothing (same 485 calls).

## 3. Decisions for Tristan (the builder takes the default, which keeps full coverage; none of them changes what main runs)

- D1. Sharding changes the required check names (`validate (ubuntu-latest)` becomes `validate (ubuntu-latest, 1)` .. `3`). Default: ship C1 and tell Tristan to update branch protection if `validate` checks are required (the builder cannot see or change repo settings). Alternative: no sharding (C2 to C6 only, about 15 % saved).
- D2. Trading coverage for speed (NOT done by default): run `-m "not slow"` on pushes to `std/**` and the full `-m ""` only on PRs to `main` and pushes to `main`. The slow-marked tests (gates concept-a, discipline gates, pdl, program constraints, others; count them with `pytest --collect-only -q -m slow | tail -1`) would not run on a std branch push. Default: all tests run on every trigger.
- D3. A ledger/PROGRESS.md-only commit skips `validate`; default keeps the ledger test coverage by running `tests/test_ledger.py` and `tests/test_progress.py` in `progress.yml`. Alternative: skip them too (T11 literal).
- D4. Every push to main runs the full validate (default) instead of cancelling a running main run; costs runner minutes only.
- D5. Shard count 3 (default). 4 shards would shorten ubuntu further but add 46 s setup per job and one more job per OS; the builder reports the per-shard times so Tristan can choose.

Defaults taken: D1 to D5 as written above, C7 skipped unless needed, no test dropped, no test moved to nightly.
