# Brief U13.8-3-apply-kinds: the `design apply` CHANGELOG entry lists each edit's kind

class: easy · role: builder · plan: §7 U13.8 (rehearsal 4; U13.3-2 compact entry) · depends on: U13.3-2 (old U4.37-2, merged) · merge order: 3rd · SLUG = `apply-kinds`

Environment: follow `plans/2026-11-20-standardization/briefs/U13.7-env.md` with every `u13.7` read as `u13.8` and SLUG=apply-kinds (Haiku trailer).

## Why (red on main)
`design apply` writes ONE compact CHANGELOG entry `{date, kind: "batch", key: "batch", old: null, new: null, why, count, keys, file}` (`core/hangar/ops/batch.py`, the `entry = {...}` line). The agent guidance counts "CHANGELOG kinds used (add / subtract / modify)" for its report, but a batch entry hides which of its edits were adds, modifies, removes or appends. Red: after a 3-edit apply (`set`, `append`, `remove`) `yaml.safe_load(CHANGELOG.yaml)[-1]` has no `kinds` key (`KeyError`).

## Where
Branch `std/u13.8-apply-kinds`. Files you may change: `core/hangar/ops/batch.py` (the entry dict, one local list, one constant, the summary), `docs/cli.md` (regenerated), `tests/test_design_apply.py` (append tests; do not edit existing ones). Nothing else.

## Exact steps (`apply_op`)
1. Next to `keys = []` add `kinds = []`; where `keys.append(key)` is done (after a successful, changed edit) also `kinds.append(_KIND[verb])` with the module constant `_KIND = {"set": "modify", "add": "add", "append": "append", "remove": "remove"}` (the names the CHANGELOG already uses for `design set`: modify, add, remove; `append` is new for this op).
2. The entry gains `"kinds": kinds` right after `"keys": keys` (same length and order as `keys`; unchanged edits appear in neither). The entry carries no values (no old/new), as now. Nothing else changes (the result `data`, messages, the no-change path).
3. The `design.apply` summary string: append ` The CHANGELOG entry lists each applied edit's key and kind (modify, add, append, remove), without values.`

## Tests (append to `tests/test_design_apply.py`; reuse its fixtures and helpers)
1. `test_changelog_lists_each_kind`: apply `[{"set": "components[center_body].mass_g", "value": 125}, {"append": "components", "value": {<the probe component the file's tests already use>}}, {"add": "flight.cl_max", "value": 1.1}, {"remove": "attachments[fc-mount]"}]` on the example copy: the last CHANGELOG entry has `kinds == ["modify", "append", "add", "remove"]`, `keys` of equal length in the same order, `count == 4`, and no key named `old`/`new` carries a value (`entry["old"] is None and entry["new"] is None`).
2. `test_unchanged_edits_are_not_listed`: an apply with one `set` to the current value plus one real `set`: `keys` and `kinds` each have length 1; `count == 1`.
3. `test_summary_mentions_kinds`: `registry()["design.apply"].summary` contains `kind`.
