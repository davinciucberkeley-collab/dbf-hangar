## Data (from brief 3)
`d.rows` is the file name of `<id>.rows.json` (may be absent or `null` on old indexes): `{"version":1,"design_id":..,"tiers":[{"tier":N,"rows":[{check_id,status,title,sentence,hint,details,parts:[{id,label}],group,source,report_only,would_be,not_applicable,fold,fold_noun}]}]}`, same tier and row order as the scorecard JSON.

## Change
1. `viewer/ui/scorecard_rows.js` exports, all pure:
   - `alignTexts(sc, rowsJson)`: returns an array per tier (same length as `sc.tiers`) of arrays per row (same length as that tier's results): the row text object when `rowsJson.tiers[i].rows.length === t.results.length` and every `check_id` matches by position; otherwise (or `rowsJson` null) a fallback object for each row `{check_id, status, title: check_id, sentence: message, hint: '', details: '', parts: [], group: 'problem', source: '', report_only: false, would_be: '', not_applicable: false, fold: false, fold_noun: 'rows'}`. A tier whose texts do not align must not break other tiers (the existing tests inject extra rows into tier 0).
   - `groupRows(sc, texts, mode, parts)` with `mode` one of `'problem' | 'part' | 'tier'`; returns `[{key, title, status, entries: [...]}]`. `problem`: groups `Needs fixing` (FAIL), `Warnings` (WARN), `Not checked` (SKIP, not `not_applicable`), `Not applicable` (`not_applicable`), `Passing` (PASS), omitted when empty; inside a group, rows of the same `check_id` family (first two segments) whose text has `fold: true` and there are 3 or more become one entry `{fold: true, title: "<title>: <n> <fold_noun>", rows: [...]}`, else one entry per row. `part`: one group per part id (title = the first label seen for it), ordered FAIL-worst first, rows of design-level families or with no parts under `Whole aircraft`; PASS rows are left out of this view. `tier`: one group per tier as today (title `T<n> <name>`, FAIL/WARN first).
   - an entry is `{row, text, tier, index}` (single) or `{fold: true, title, status, rows: [entry...]}`.
2. `renderScorecard` in `designs.js`: after loading `sc`, `let rowsJson = null; if (d.rows) try { rowsJson = await getJSON(d.rows); } catch { rowsJson = null; }`; `texts = alignTexts(sc, rowsJson)`; set `r.text = texts[i][j]` on every result object (so the inspector can read it); keep the existing `vp.main.setStatus(...)` and `setInspectorScorecard(sc)` calls and the stale-selection guard.
   - A group switch above the rows: `<div data-testid="group-by">` with three buttons `data-testid="group-problem"`, `group-part`, `group-tier`, labels `Problem`, `Part`, `Tier`; the active one has class `active`; default `problem`; the choice is a module variable kept across designs; clicking re-renders only the rows area.
   - One row (single entry) keeps today's element and attributes (`div.result.<STATUS>`, `data-testid="check-row"`, `data-check-id`, `data-parts`, `has-parts`, click/Enter behaviour via `rowParts`, unchanged) and adds the attribute `title="<check_id>"` (hover shows the machine id). Content: `.top` = badge + `span.title` (bold plain name) + part chips (`span.chip`, one per `text.parts`, text = label; chip click does the same as the row click) + `span.rtag` "report-only until 2026-12-08" with ` (would be X)` when `report_only`; then `div.sentence` = sentence; `div.hint` = `Fix: <hint>` when hint; `span.cid` (small grey, the machine id, always in the text); `details.raw` with summary `details` holding `details` and, when `source`, `Limit source: <source>`. Rows without a registry text (fallback) render as today (id + message).
   - A folded entry renders `details[data-testid="check-fold"]` with summary = badge + title, then the shared sentence/hint of its first row, then each member as a normal single row.
   - `Not applicable` and `Passing` groups are `<details>` closed by default; the groups `Needs fixing` and `Warnings` open; `Not checked` open when it has 20 entries or fewer, else closed.
   - Rows must remain reachable by `[data-check-id]` in the DOM in every view (a closed `details` is fine; the part-check click in the inspector already opens the enclosing `details`; it must also switch to the group view that contains the row: if the row is not found, set the view to `tier`, re-render and retry once).
3. `inspector.js::checksList`: each `li` keeps `data-for`, the badge, the `span.cid` with the id and the click behaviour; replace the message span by `span.title small` (`r.text.title`) followed by `span.msg small` (`r.text.sentence`) when `r.text` exists, else the old `r.message`. Add `title=r.check_id` on the `li`.
4. `style.css`: append rules for `.result .title` (bold), `.chip` (small rounded label, accent border, cursor pointer), `.rtag` (muted small), `.sentence`, `.hint` (muted, left border), `.result .cid` made small and muted when it follows a `.title` (`.title ~ .cid`), `details.raw summary` (small), `.group-by button.active`. No colour literals: use the existing CSS variables.
5. Old index (no `rows` key): everything renders exactly as before this brief except the group switch (view `tier` is then forced and the switch is hidden).
