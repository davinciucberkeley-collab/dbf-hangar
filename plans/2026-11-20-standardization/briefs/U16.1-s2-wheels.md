**PDL 1.3 field introduced here (the schema is already 1.3 from S1, no new bump): `attachments[].articulation.type: continuous`** (a joint with no range that spins without limit; `range_deg` and `poses` are then not allowed). Everything else is generator params (`landing_gear.wheels`, `landing_gear.axle_d`, the new `wheel` generator), not PDL.

Ordering: this brief edits `core/hangar/geom/airframe.py` (not the wing or tail generators, so it does not collide with U15.1 or U16.2) and `schema/plane.schema.json`, `docs/pdl/reference.md` (U15.1 and S1 touch them too: rebase, regenerate the reference, never hand-merge it).

## What is wrong today
`landing_gear` (`core/hangar/geom/airframe.py:80-102`, `_gear_build`) unions legs, axles and wheels into ONE mesh: one component, no axle joint, the wheels cannot turn, and T1 contact is judged per component, so a leg touching the airframe hides a nose wheel that is not attached (Tristan's observation).

## Decision (default taken)
- `landing_gear` gets `wheels: choice merged (default) | separate`. `merged` = today's code, unchanged (bit-identical vertices).
- `separate` builds ONLY legs, axle stubs and the nose fork (no wheels, no wheel hub). Geometry rules, per side `s` in (-1, +1) for the main gear, `n = main_wheels` must be 1 (otherwise `_gear_check` error `wheels: separate needs main_wheels 1`):
  - `axle_d = p["axle_d"] or 0.5 * leg_d` (new param `axle_d`, number, default 0 = 0.5 x leg_d, doc `axle stub diameter, mm; 0 = half the leg diameter; only used with wheels separate`).
  - Main leg inboard of the wheel: bottom at `(main_x, s * yb, axle_z)` with `yb = track/2 - wheel_w/2 - leg_d/2 - 0.5`; top at `(main_x, s * (yb - off), attach_z)` with the same `off` as today. (The leg stands beside the wheel, so wheel and leg never overlap.)
  - Axle stub: a tube along y from `y_in = s * yb` to `y_out = s * (track/2 + wheel_w/2 + 1.0)`: centre `((y_in + y_out)/2)`, length `|y_out - y_in|`, diameter `axle_d`, at `(main_x, centre, axle_z)`.
  - Nose or tail fork (`fw = front_wheel_d or wheel_d`, `fld = front_leg_d or leg_d`, `axle_z_f = ground_z + fw/2`): strut from `(front_x, 0, front_attach_z or attach_z)` to `(front_x, 0, crown_z)` with `crown_z = axle_z_f + fw/2 + 1.0`; crown bar `tube("y", (front_x, 0, crown_z), 2 * yp, fld)`; two prongs `_segment((front_x, s*yp, crown_z), (front_x, s*yp, axle_z_f), fld, 0.0)` for s = -1, +1; axle stub `tube("y", (front_x, 0, axle_z_f), 2 * yp, axle_d)`; with `yp = wheel_w/2 + fld/2 + 0.5`. Everything unioned into one watertight mesh (`kernel.union`), one part.
  - `_gear_check` additions: `wheels: separate` with `main_wheels > 1` error as above; `axle_d`, when given, must be `< wheel_w` and `<= leg_d`.
- New generator `wheel`, registered in `core/hangar/geom/airframe.py` beside `landing_gear` via `register(Generator("wheel", {...}, _wheel_build, check=_wheel_check))`: params `wheel_d` (number, required, exclusive_minimum 0, `wheel diameter, mm`), `wheel_w` (number, required, exclusive_minimum 0, `wheel width, mm`), `shape` (choice `disc` | `tyre`, default `tyre`, same meaning as landing_gear `wheel_shape`), `bore_d` (number, default 0, minimum 0, `axle bore diameter, mm; 0 = solid; keep it within 4 mm (2 x attach_tolerance_mm) of the axle so the joint point at the axle centre stays on the wheel`). The wheel is centred on its local origin with its axis along y, so the component `position` is the axle centre. Build: `_gear_wheel({"wheel_shape": shape}, (0, 0, 0), wheel_w, wheel_d)` then, when `bore_d > 0`, `kernel.difference(mesh, [kernel.tube("y", (0, 0, 0), 2 * wheel_w, bore_d)])`. `_wheel_check`: `bore_d` must be `< 0.5 * wheel_d` and `< wheel_w * 4`.
- PDL: `articulation.type` enum `["revolute", "continuous"]`; `required` is `[type, pivot, axis]`; `allOf`: `if type == revolute then required range_deg`, `else (continuous) range_deg and poses are not allowed` (`"not": {"anyOf": [{"required": ["range_deg"]}, {"required": ["poses"]}]}`). The description gains: `v1.3: type continuous = spins without limit (a wheel on its axle); no range_deg, no poses.`
- Semantics for a continuous joint: T1 does no pose sweep for it (a wheel is axisymmetric; no `range min/max/sweep` configurations, no `poses`); `T1.articulation` checks axis not zero, pivot within `attach_tolerance_mm` of both parts, loop rule, and prints `continuous` instead of the range; T6.undriven skips it; it can not be a mechanism driver, follower or `expect` target (FAIL `mechanism <id>: continuous joint <label> cannot be a driver or follower`); Studio Physics gets one spin sweep per continuous joint that is not in any mechanism, named `spin-<attachment label>`, input range `[0, 360]`, 1 degree steps (also when the design has a `mechanisms` block).
- T0.version: extend `_tier0_v13` (added by S1): any attachment whose `articulation.type` is `continuous` in a file below 1.3 gives `T0.version` FAIL `articulation.type continuous needs schema_version "1.3"`.
