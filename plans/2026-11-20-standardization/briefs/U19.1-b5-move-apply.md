## Exact steps and outputs
### 1. Pending-moves model and gizmo (`viewer/vp/move.js`, `scene.js`)
- Units: PDL positions are body-frame mm lists. A part's position in `parts.json` (`position_mm`) is the old value; the new value is `old + delta` where `delta` (mm) = `sceneToMm(edit offset)` from `vp/transforms.js` (B4; formula `[dx*1000, -dz*1000, dy*1000]`, rounded 0.1). All rounding goes through that one function.
- `Viewport.moveBy(id, dMm, { attached })` (dMm body mm `[dx, dy, dz]`): refuses (returns `false`, no change) when `explode.t > 0`, when the part is `visual_only`, or when the id is unknown; otherwise computes the target set = the part plus, when `attached` (default: the toggle's value, true), all its descendants from `parts.json` (`parent` links), calls `transforms.setEdit(id, current + mmToScene(dMm))` for each, re-composes (B4), applies appearance, updates `dirty`, notifies app.js. Returns `true`.
- `Viewport.move(id, dMm)` hook = `moveBy(id, dMm, { attached: toggle value })`. `Viewport.pending()` returns an array, one entry per part with a non-zero edit, ordered by `parts.json` order: `{ id, from_mm: [x,y,z], to_mm: [x,y,z], delta_mm: [x,y,z] }` with `from_mm = position_mm`, `delta_mm = sceneToMm(edit)`, `to_mm = from_mm + delta_mm` (each rounded 0.1, `-0` shown as `0`). `Viewport.revertMoves()` clears every edit (`setEdit(id, null)`), notifies. `state()` (B2/B4) gains `tool: 'select' | 'move'`, `gizmo: <id> | null`, `pending: <count>`.
- Gizmo: `viewer/vp/move.js` lazily imports `TransformControls` from `three/addons/controls/TransformControls.js` on first use of the Move tool. Create `new TransformControls(camera, renderer.domElement)`, `setMode('translate')`, `setTranslationSnap(0.001)` (1 mm; held Shift: `0.0001`, updated on keydown/keyup), `setSize(0.8)`, add `controls.getHelper()` to the scene (three 0.170+ API). Because TransformControls writes `object.position` and component nodes must only be written by `transforms.js`, attach it to a proxy `THREE.Object3D` (not in the model) placed at the selected part's current centre (`centres` from B4 plus its edit offset). On `dragging-changed` set `orbit.enabled = !event.value`. On `objectChange` compute the increment of the proxy since the last event, convert `sceneToMm`, and call `moveBy(id, inc, { attached })` for the primary selected part (with several selected, for each selected part that is not a descendant of another selected part). On drag end re-place the proxy at the new centre. Detach and hide the helper when the tool is Select, nothing is selected, the selected part is `visual_only`, or `explode.t > 0`. `dispose()` (B0) removes and disposes the controls.
- Axis keys while the Move tool is active (document keydown, ignored inside inputs): `x` shows only the X axis (`showX` true, others false), `y` only body Y (scene Z), `z` only body Z (scene Y); `Escape` first restores all three axes if one was locked, otherwise clears the selection as B2 does. Body to scene axes: x -> x, y -> -z, z -> y.
- Toggle `[data-testid="move-with-attached"]` (checkbox, default checked) lives in the tool group (step 6).

### 4. Review & Apply (Studio only: `viewer/modes/move-apply.js`, `edit.js`)
- `edit.js` `boot()`: after `V.onScorecard = actionBar;` add `V.studio = { op, designPath, toast, dialog, field, primary };` and `import('./move-apply.js').then((m) => m.default(V)).catch((e) => console.warn('move apply failed to load', e));` (these two additions only).
- `move-apply.js` default export `(V)`: adds the Review & Apply button (`data-edit`) to `#apply-bar` and keeps it in step with the bar.
- Clicking it opens `V.studio.dialog('Review moves', [...], primary('Apply', ...))` (the same helpers `edit.js` uses), with `dlg.classList.add('wide')`. Body:
  1. a table, one row per `pending()` entry: id, `components[<id>].position`, `[old] -> [new]` (numbers as `String(n)` joined by `, `, e.g. `[140, 0, -27.5] -> [150, 0, -27.5]`);
  2. warnings (class `warn`, `data-testid="apply-warnings"`), each shown when it applies, built only from data already in `parts.json` and the pending list: (a) "`<id>` has an expression position (`$name`); Apply replaces it with plain numbers" for every pending part with `position_expr`; (b) "the pivot of joint `<label>` is a fixed point in plane.yaml and does not move with `<id>`: check T1.articulation after the re-run" for every attachment in `parts.json` `attachments` whose child part is `articulated` and whose parent or child is in the pending set; (c) "`<id>` has cavities that stay where they are: a part inside one will not carry it with it" for each part with `has_cavities` that is NOT pending while some part is pending; (d) "N attachment(s) touching moved parts keep their literal joint location: T1.attachment may flag them" when at least one attachment has a pending parent or child but both are not pending (a joint between moved and unmoved part);
  3. the exact CLI line (`<pre data-testid="apply-cli">`): `plane design set designs/<design id> "components[<a>].position" "[x, y, z]" --also "components[<b>].position=[x, y, z]" ... --kind modify --why "<why as typed so far>"` (updates as the why is typed; `--also` omitted for one part);
  4. a text input `[data-testid="apply-why"]` (required, placeholder "One line: why this move").
- Apply handler (inside `primary(...)`, button `data-testid="apply-go"`): `why = input.trim()`; empty -> `throw new Error('Say why in one line.')`. Otherwise ONE call: `await op('design.set', { path: designPath(id), key: 'components[' + first.id + '].position', value: '[' + first.to_mm.join(', ') + ']', why, kind: 'modify', also: rest.map(p => 'components[' + p.id + '].position=[' + p.to_mm.join(', ') + ']') })` (`id` = `V.selected()`). On success: `vp.clearMovesAfterSave()` (drops edits without redrawing; the reload that follows replaces the model), close the dialog, `toast('Saved N moved part(s). Checks are re-running.')`, `await V.reload(id)`. An op error shows in `.dlg-err` and keeps the pending moves.
- The existing rescan and check job (A10) and the `rev` poll then reload the design; no new server route and no change to `core/hangar/studio.py`.

### 5. Keep the view across the reload (`vp/scene.js`, `app.js`)
`Viewport.show(design)`: when `this.mountInfo?.id === design.id` the camera position, target and zoom are kept (skip `fit`), and `app.js` re-applies the previous selection filtered to the new model's ids and the previous hidden/ghost sets (B2/B3 sets) after `show()` resolves. A different design id behaves as today (fit, clear).

### 6. Moved marks (`ui/tree.js`, `ui/inspector.js`, `vp/materials.js`, `ui/timeline.js`)
- Tree rows of pending parts: `data-moved="1"` and a small `moved` tag. Inspector: for a selected part with a pending move a `<span data-testid="tag-moved" class="tag">moved</span>` and three number inputs `[data-testid="nudge-x"]`, `nudge-y`, `nudge-z` showing the part's `delta_mm`; editing one (on `change`) calls `moveBy(id, newDelta - currentDelta, { attached: toggle })` so the displayed delta equals what was typed (0.1 mm resolution). The inputs are present on Pages too (view only), disabled while `explode.t > 0`.
- `applyAppearance` (B3): edge lines of pending parts use colour `0xf97316` (the CG orange) and opacity 0.9, regardless of selection dimming.
- Timeline (B4): while `pending().length > 0` the play button, scrub and mechanism select are disabled and `#timeline` gets class `blocked` plus a text `"Apply or revert moves to play"` (`data-testid="tl-blocked"`). Mechanism transforms are about rest pivots (spec §2.3).

### 7. Discard prompt (`app.js`)
Before design change (`choose`, `assign`, sidebar), mode change (`setMode`) and `reload(selectId)` initiated by the user (not the poll after an Apply): if `pending().length > 0`, `if (!window.confirm('Discard ' + n + ' unsaved move' + (n === 1 ? '' : 's') + '?')) return;` then `revertMoves()`. Browser `beforeunload` is not added. The `rev` poll reload after a rescan keeps pending moves only for the same design id and when the model's component ids are unchanged; otherwise it discards them silently after toasting `"Unsaved moves were discarded because the design changed on disk."`.
