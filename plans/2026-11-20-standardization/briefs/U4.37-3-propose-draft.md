## Why (A400M rehearsal gap 24; and a side effect found in the code)
- PR title is rewritten to `design(<id>): <title>` and there is no draft option, so a "do not merge" PR is an ordinary open PR.
- `propose_op` ends with `git switch <start branch>`, which removes the just-committed design from the working tree (for a new design its folder disappears; for an edit the file goes back to the old text). The session cannot keep working on it.

## Exact steps (all in `propose_op`)
1. Signature `def propose_op(path: str, title: str, *, draft: bool = False) -> OpResult:`; summary gains the sentence ` With draft=True the PR is opened as a draft. The PR title is the title as given; the commit subject is design(<id>): <title>. The design stays in the working tree.`
2. The `gh pr create` argv: replace `"--title", subject` by `"--title", title`; append `"--draft"` as the last element when `draft`. The commit subject stays `design(<id>): <title>`; the branch name and body are unchanged.
3. Working tree: after the existing `try/finally` (which still ends with `git switch <start>`), and only when the push and PR creation succeeded, run `_run(["git", "-C", root, "checkout", branch, "--", ddir], root)` and then `_run(["git", "-C", root, "reset", "-q", "--", ddir], root)` (restores the proposed files into the working tree and unstages them). Compute `url` from `out` as today before these two calls.
4. Regenerate `docs/cli.md`.
