## DECISION on the four D-212 ids (tactician; the conductor may overrule before the build)
The conductor's default `D-212, D-212-r2, D-212-r3, D-212-r3m` is NOT used: a hyphen suffix fails the ledger id pattern and would need a schema change plus an edit of a test that rejects it. Use the letter suffix that the pattern and `D-183b` already use: first version `D-212`, rev 2 `D-212b`, rev 3 `D-212c`, rev 3 minors `D-212d`. Rule in code: id = `D-<number>` from the start of the first cell; if the text after the id matches `^\s*rev (\d+)( minors)?`, the suffix is `chr(96 + n)` (rev 2 -> b, rev 3 -> c), and with `minors` the next letter (`chr(97 + n)`: rev 3 minors -> d). A source id that already carries letters (`D-183b`) keeps them and gets no further suffix. The ledger `source` field is `CHANGE-LOG#<computed id>`.

## Exact steps and outputs
1. In the loop, take `first = cells[0].replace("*", "").strip()`, and `m = re.match(r"^D-(\d+[a-z]*)\b(.*)$", first)`. No match: if `re.match(r"^[A-Za-z]+-\d+", first)` (a numbered row of another kind, such as T-096) call `log(f"row without a D-number skipped: {first[:60]}")`; either way `continue` (header and separator rows are skipped silently). No counter changes for skipped rows.
2. `rest = m.group(2).strip()`; apply the suffix rule above to get the id. `text = _clean(f"{rest} {cells[1]}")` (`_clean` also collapses spaces, so a bare-id row, where `rest` is empty, yields exactly the text the old code produced, `_clean(cells[1])`: existing ids and test values must not change).
3. A computed id seen twice in the same file is counted in `duplicates` and the first row wins (existing rule). The returned dict keeps exactly the keys `changelog, decisions_md, skipped, duplicates`.
