# Brief U13.7-4-nested-remove: `set --kind remove` and `apply` remove accept elements of nested lists such as bom.items (T141)

class: hard · role: builder-plus · plan: §7 U13.7 (T141; W31-R §19) · depends on: U13.6-2 (old U4.41-2, merged: flow-list removal) · merge order: 4th · SLUG = `nested-remove`

Environment: follow `plans/2026-11-20-standardization/briefs/U13.7-env.md` with SLUG=nested-remove.

## Red on main (2026-11-25)
`pdledit.remove_element("bom: {items: [{id: a}, {id: b}]}\n", "bom.items[a]")` and the same on a block layout (`"bom:\n  items:\n    - id: a\n    - id: b\n"`) both raise `OpInputError bom.items[a]: remove takes a top-level list element name[id]; a nested path (one field, or a list below an element) is not supported`. `design set --kind remove` and `design apply {remove: ...}` call this function, so a BOM line, a wiring harness or a mechanism cannot be removed (`bom.items`, `wiring.harnesses`, `assembly.sequence`, `transport.disassembly` are all nested lists).

## Exact steps (`remove_element`)
1. Replace the two guards (`len(steps) > 2` -> error, `len(steps) != 2 or steps[1][0] != "id"` -> error) by: the LAST step must be an id selector (`steps[-1][0] == "id"`), else OpInputError `f"{key}: remove needs a list element like name[id]; this is not one"`; the step before it must be a key step (`steps[-2][0] == "key"`), else OpInputError `f"{key}: remove needs a list named by a key, like bom.items[id]"` (a list inside a list is not supported). Any path of key and id steps before that is accepted (`bom.items[x]`, `components[wing].children[c1]`). The existing "remove by index" refusal stays first.
2. Everywhere the function uses `steps[1][1]` (the element id for the comment regex) use `steps[-1][1]`; everywhere it uses `steps[0][1]` or `root.lc.key(name)` for the list's header line, use the list's own key: `list_key = key[: key.rindex("[")]` (the key text up to the last selector), `_, mapping, _, ref = walk(root, list_key)` (the mapping that holds the list and the list's key name `ref`), `h = mapping.lc.key(ref)[0]`, and the header regex uses `ref` instead of `name`.
3. The flow-list branch and the block branch otherwise stay as they are (they already work from `seq`, the parent list returned by `walk`). A list that is one line inside a flow mapping (`bom: {items: [...]}`) uses the flow branch; a block list nested under block mappings uses the block branch; the only-element case writes `items: []` on the list's own header line with its original indentation.
4. `ops/edit.py`: in the `design.set` summary string replace `deletes one list element addressed name[id]` by `deletes one list element addressed name[id] or a.b[id] for a nested list`. Regenerate `docs/cli.md`.
