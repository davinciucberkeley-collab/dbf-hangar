## Why (red on main)
`plane design apply` -> `No such command 'apply'`. The A400M rehearsal needed about 150 single `design set` calls, 30-70 s each (each call reloads, validates, regenerates the changed parts and re-runs interference), about 50 minutes; its PR carried a 4,399-line CHANGELOG.yaml. Documented single-edit forms: `design set` (value of an existing scalar, `--kind add` of a scalar or one-line value, `--kind remove`) and, from U13.2-1, `design add <path> <list> --value '{id: ...}'` (the one documented way to create a component, attachment or bom line). The undocumented `set --kind add components[id].type --also ...` still works and stays as is; the batch file uses `append` for new elements.

## Edit file format (YAML list, one mapping per edit; exactly one of the four verbs per mapping)
```
- {set: components[wing].mass_g, value: 250}           # existing scalar (like design set, kind modify)
- {add: flight.cl_max, value: 1.2}                     # new key, scalar or {mapping} / [list] value (like set --kind add)
- {append: components, value: {id: probe, type: other, geometry: {point_mass: {}}, position: [10, 0, 0], mass_g: 2}}   # new list element (U13.2-1) ; a scalar value goes to a one-line [list] (like --append)
- {remove: "components[probe]"}                        # one list element (like set --kind remove)
```
Values are YAML data, not strings (no `: `-in-text trap). Any other key, two verbs in one mapping, a missing `value` (except `remove`), or a non-list file -> OpInputError `"edit <n>: <what>"` with `n` counted from 1.

## Interface (exactly this)
`core/hangar/ops/batch.py`:
```python
@op(name="design.apply", summary="Apply many edits from a YAML file (set / add / append / remove) in one atomic step: one schema check, one regeneration and one interference pass for the whole batch, one compact CHANGELOG entry.", mutates=True, render=lambda r: "\n".join(r.messages))
def apply_op(path: str, *, edits: Path, why: str) -> OpResult:
```
Steps:
1. `plane = edit._plane(path)`, `text = edit._text(plane)` (`from . import edit`); `why` empty -> OpInputError "why must not be empty"; read and parse `edits` (a path; missing -> OpInputError "no such file"); validate the shape as above.
2. `before = yaml.safe_load(text)` (use `yamlfast.safe_load` when `hangar.yamlfast` exists). `working = text`. For each edit in order, using only `pdledit` functions on the working text, never touching disk:
   - `set`: `data = load(working)`; `pdledit.get_value(data, key)` (raises the "no key" error); value must be a scalar (list/dict -> OpInputError "edit n: set takes a scalar; use add or append"); if equal and same type -> count as unchanged and continue; else `working = pdledit.patch_text(working, key, value)`.
   - `add`: key must not exist (`pdledit.exists`), else OpInputError "edit n: <key> is already set"; `working = pdledit.add_value(working, key, value)` (a dict/list value must be non-empty).
   - `append`: dict value -> `working, _, _ = pdledit.append_element(working, key, value)`; scalar value -> `pdledit.append_item(working, key, value)`.
   - `remove`: `working, _ = pdledit.remove_element(working, key)`.
   Wrap each `OpInputError` as `OpInputError(f"edit {n}: {e}")`. No schema check between edits (an attachment may be appended before its child component).
3. After the loop: the same three guards `set_op` runs, once, on the final text: fresh `expression_errors` (`from ..geom.params import expression_errors`), `pdledit.check_schema(before, after, "batch")`, `regeneration_report(text, working, plane)` imported inside the function as `from ..geom.resolve import regeneration_report` (so a test can count calls on `hangar.geom.resolve.regeneration_report`).
4. CHANGELOG: ONE entry `{"date": stamp, "kind": "batch", "key": "batch", "old": None, "new": None, "why": why, "count": <edits applied, unchanged ones excluded>, "keys": [<each edit's key, in order>], "file": edits.name}`; write it with `edit._write_with_log(plane, text, working, [entry])` (added by U13.2-1; if its signature differs, adapt the call, do not change it). The values are not logged (git holds them in the plane.yaml diff).
5. Return `OpResult(True, {"count": n, "unchanged": u, "verbs": {"set": a, "add": b, "append": c, "remove": d}}, [f"applied {n} edits ({a} set, {b} add, {c} append, {d} remove; {u} unchanged)"], changed_files=[str(plane), str(log)])`, plus the same "regenerated ... mass ... CG ..." and "moved N part(s) ... interference: X new, Y cleared" / "new interference:" / "cleared:" / "still failing" message lines `set_op` builds (copy those f-strings; same keys `regenerated`, `interference`, `still_failing` in `data`). When nothing changed (all unchanged) write nothing and return `OpResult(True, {"count": 0, ...}, ["no changes"])`.
6. CLI `plane design apply <path> --edits <file> --why "<text>"` and MCP `design_apply` come from the registry; do not edit `cli.py` or `mcp_server.py`. Regenerate `docs/cli.md`.
