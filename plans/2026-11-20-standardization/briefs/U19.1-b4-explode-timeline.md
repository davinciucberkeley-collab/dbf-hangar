## Exact steps and outputs
### 1. `viewer/vp/transforms.js`
- Exports `mmToScene(d)`: `[dx, dy, dz]` body mm -> `THREE.Vector3(dx/1000, dz/1000, -dy/1000)` (a direction/offset, same axes as `app.js`'s `mmToScene` point conversion), and `sceneToMm(v)`: `Vector3` or `[x,y,z]` scene m -> `[v.x*1000, -v.z*1000, v.y*1000]` each rounded to 0.1 (`Math.round(n * 10) / 10`, and `-0` normalised to `0`).
- `export class Transforms { constructor(vp) }` keeps per component id: `edit` (Vector3, scene m, default zero), `explode` (Vector3, default zero), `mech` (Matrix4 or null). API: `setEdit(id, v|null)`, `setExplode(id, v|null)`, `setMech(id, m|null)`, `clearAll()`, `offset(id)` (returns the explode offset as `[x,y,z]` scene m), `isMoved(id)` (node matrix differs from identity by more than 1e-12 in any element), `recompose(id)`.
- `recompose(id)`: `node = vp.model.getObjectByName(id)`; `node.matrixAutoUpdate = false`; `node.matrix.makeTranslation(explode).multiply(translation(edit)).multiply(mech ?? identity)` (order: `T(explode) * T(edit) * mech`); `node.matrixWorldNeedsUpdate = true`; `vp.dirty = true`. When all three layers are empty the matrix is set to identity exactly.
- Nothing else in `viewer/` may assign `node.matrix`, `node.position` or call `matrix.copy` on a component node (`grep -rn "\.matrix\b" viewer` must list only transforms.js, plus read-only uses). `vp.transforms` is public (hooks). Instantiate it in `Viewport.show()` after the model is built and discard it in `clear()`.

### 2. Explode (`vp/scene.js` + `transforms.js`)
- At load (after materials are prepared, before any layer is set) store `this.centres`: for each component node with a mesh, the world-space `Box3` centre (scene m). Part tree data: fetch `getJSON(design.parts)` (B2) in `show()` (not on failure: then `this.parts = null` and `explode()` returns without effect and `state().explode = null`).
- `explode(t, level = 'all', strategy = 'hierarchy')`: `t` in 0..1; `level` `'all'` or an integer 1..max depth; `FACTOR = 1.5`.
  - hierarchy: iterate parts in order of increasing depth. `C(p)` = the centre of the nearest ancestor-or-self with a mesh (model centre, i.e. the root's centre, when none). Root: `D(root) = 0`. For a part `p` with a parent: `own(p) = (C(p) - C(parent)) * t * FACTOR` when `p.depth <= L` (`L` = level, or max depth for `'all'`), else `0`; `D(p) = D(parent) + own(p)`. Parts with `parent null` that are not the root: `own = (C(p) - C(root)) * t * FACTOR`, `D = own`.
  - radial: `D(p) = (C(p) - C(root)) * t * FACTOR` when `p.depth <= L`, else `D(parent)`; root 0.
  - Apply with `transforms.setExplode(id, D)` for every id in the scene; `t == 0` sets `null` for all (matrices return to exact identity).
- `state()` (B2) gains `explode: { t, level, strategy } | null`, `offsets: { id: [x, y, z] }` (explode offset in scene m rounded to 1e-6, drawn ids only) and `moved: [ids whose node matrix is not identity]`.
- Hook `vp.explode(t, level, strategy)` (the same function). Before any pick the model's matrices must be current: `pickRay`/`pickAt` (B3) call `this.model.updateMatrixWorld(true)` first (add that call in scene.js's wrappers, not in pick.js).
- Controls: `<div id="explode-bar" class="view-bar">` in `.vp-wrap`: slider `[data-testid="explode-slider"]` (0..1000, value 0), `<select data-testid="explode-level">` (`All`, then `1..maxDepth` filled when `parts.json` is loaded), `<select data-testid="explode-strategy">` (`hierarchy`, `radial`). Any change calls `vp.explode(slider/1000, level, strategy)`. A design switch resets the controls to 0 / All / hierarchy.

### 3. Timeline (`viewer/ui/timeline.js`, replaces `modes/physics.js`)
- `export function renderTimeline(ctx, d)`: fills `#timeline` (inside `#mode-designs`, below `.vp-wrap`; hidden when `d.mechanisms` is falsy). Controls: `<select data-testid="tl-mech">` (mechanism ids from `getJSON(d.mechanisms)`), `<button data-testid="tl-play">Play/Pause</button>`, `<input type="range" data-testid="tl-scrub">` (0..steps-1), `<select data-testid="tl-speed">` (`0.5`, `1`, `2`; default 1), `<label><input type="checkbox" data-testid="tl-loop"> loop</label>` (default off), readouts `<span data-testid="tl-input">` (input degrees, 0 decimals) and `<span data-driver>`, and one `<span data-follower="<name>">` per follower (1 decimal), exactly as `physics.js` renders them today (same data: `mech.steps[i].input_deg`, `.followers`, `.transforms`).
- Playing uses `requestAnimationFrame`, not `setInterval`: accumulate `dt` ms; one step per `60 / speed` ms; at the last step stop (loop off) or return to step 0 (loop on). Pause keeps the index. Changing mechanism stops playing and resets to step 0.
- Applying step `i`: for each id touched by the mechanism (union of keys of all steps' `transforms`) `vp.transforms.setMech(id, null)`; then for each `[id, m]` of the step: `setMech(id, new THREE.Matrix4().set(...m).premultiply(T).multiply(TI))` where `T` is the body-mm to scene-m matrix constant that `physics.js` has (`new THREE.Matrix4().set(1e-3, 0, 0, 0, 0, 0, 1e-3, 0, 0, -1e-3, 0, 0, 0, 0, 0, 1)`) and `TI = T.clone().invert()` (same math as today). The removed "node not at rest origin" guard is not needed: nodes are at identity (spec A6). Moving to another design or mechanism calls `setMech(id, null)` for all touched ids.
- Explode and the timeline compose through `recompose` (no extra code).
- `modes/designs.js`: after `renderScorecard`, call `renderTimeline(ctx, d)`; `el.dataset.ready = '1'` is still set last.
