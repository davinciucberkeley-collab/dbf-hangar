### 1. Value parsing (`pdledit.py`)
Add:
```python
def parse_value(raw: str):
    """Scalar as parse_scalar does; or, when raw.strip() starts with '[' and ends with ']' (or '{' ... '}'), the parsed list or mapping."""

def render_flow(v) -> str:
    """One-line YAML flow text for a scalar, list or mapping; scalars via render_scalar."""
```
`parse_value` rules:
- Strip `raw`. If it starts with `[` and ends with `]`, or starts with `{` and ends with `}`: `yaml.safe_load` it (a `yaml.YAMLError` becomes `OpInputError(f"cannot read value {raw!r}: {e}")`, as in `parse_scalar`); the result must be a list or dict, else `OpInputError`.
- Any other `raw` (including block-looking text such as `a: b` or `- x`): return `parse_scalar(raw)` unchanged, so it keeps raising "is a mapping or list; give one scalar".
- Refuse an empty collection (`[]`, `{}`, also nested anywhere) with `OpInputError(f"value {raw!r}: empty list or mapping not allowed")`.

`render_flow` rules:
- list -> `[` + `", ".join(render_flow(x))` + `]`; dict -> `{` + `", ".join(f"{k}: {render_flow(x)}")` + `}`; anything else -> `render_scalar(v)`.
- A mapping key must be a `str` matching `[A-Za-z_][A-Za-z0-9_-]*`; otherwise `OpInputError(f"unsupported mapping key {k!r}")`. Types `render_scalar` rejects keep raising its error.

### 2. Splice (`pdledit.py`)
- `_emit`: the final line becomes `f"{sp}{v}: {render_flow(new)}"` (was `render_scalar`). A collection is thus always one flow-style line under a new block key. Scalars produce the same bytes as before. Nothing else in `_emit` changes.
- Add `_nest(rest, new)`: `rest` is a list of steps; every step must be `("key", name)`, otherwise `OpInputError("cannot add this value without rewriting other text; edit the file by hand")`. Return `new` when `rest` is empty, else `{rest[0][1]: _nest(rest[1:], new)}`.
- `add_value`, flow-mapping branch (`isinstance(node, dict) and node.fa.flow_style()`): today it refuses when `len(rest) != 1`. Change it: refuse (the existing `hand` error) when `end < 0` or when any step in `rest` is not a `"key"` step; otherwise `value_text = render_flow(_nest(rest[1:], new))` and the line becomes `f"{head}{sep} {rest[0][1]}: {value_text}{lines[line_no][end:]}"`. So `attachments[E-MEC-02].articulation` with a mapping appends `, articulation: {...}` before the closing brace of that one line, and `attachments[E-MEC-02].extra.k` with `1` appends `, extra: {k: 1}`.
- Everything else in `add_value` stays: CRLF handling, Verify 1 (`yaml.safe_load(out) == expected`, `expected` built by `_create` with the same collection), Verify 2 (only `equal`, `insert`, and the one allowed one-line `replace` of the flow line that received the key), the "already set" refusal, the multi-line flow mapping refusal (the closing brace is not on the key's first line, so `_close_brace` returns -1), the flow-list refusal, and the by-index refusals.
