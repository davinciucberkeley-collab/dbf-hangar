# Brief U19.2-3-rows-json: `<id>.rows.json` next to the scorecard for Studio

class: easy · role: builder · plan: §7 U19.2 (P315) · spec: `plans/2026-11-20-standardization/u19.2/spec.md` section 5 (Studio) · depends on: U19.2-1-registry merged · branch `std/u19.2-3-rows-json`, SLUG `u19.2-3-rows-json`

Environment, byte-identical JSON check and export-hash check (this brief needs both): `plans/2026-11-20-standardization/briefs/U19.2-env.md`.

## Files allowed
- `core/hangar/index.py` (only `design_entry`, plus one new helper `rows_json`)
- `tests/test_build_index_design.py` (add tests; do not change existing ones)

## Change
1. New `def rows_json(card, design) -> dict` in `core/hangar/index.py` (import `describe_card` and `load_registry` from `hangar.gates.describe` inside it). Returns
   ```
   {"version": 1, "design_id": card.design_id, "tiers": [ {"tier": t.tier, "rows": [ <row>, ... ]} ... ]}
   ```
   with tiers and rows in exactly the order and lengths of `card.tiers[i].results`, and each `<row>` the dict
   `{"check_id", "status", "title", "sentence", "hint", "details", "parts": [{"id", "label"}], "group", "source", "report_only", "would_be", "not_applicable", "fold", "fold_noun"}` built from `RowText` (`fold` = the registry's `fold` flag for the family, default false; `fold_noun` = registry value, default `"rows"`).
2. `design_entry`: after the `.scorecard.json` write, write `<fid>.rows.json` (`dumps(rows_json(card, design)) + "\n"`) and add the key `"rows": f"{fid}.rows.json"` to `entry` (next to `"scorecard"`). If `rows_json` raises, write nothing and set `"rows": None` (same try/except pattern as the `mechanisms` block: a text problem must never break the index). Do not change `.scorecard.json`, `.parts.json` or anything else.
3. The error-entry dict (around line 244, the one with `"scorecard": None`) gets `"rows": None`.

## Tests first (`tests/test_build_index_design.py`; write, run, paste the failing summary, then implement)
Follow the existing tests in that file for how a design is built and `design_entry` is called.
1. `test_rows_json_written_and_aligned`: after `design_entry(...)`, `<fid>.rows.json` exists, `entry["rows"] == f"{fid}.rows.json"`, the tier count and per-tier row count equal those of `<fid>.scorecard.json`, and for every row `check_id` and `status` equal the scorecard row's.
2. `test_scorecard_json_unchanged_by_rows`: the bytes of `<fid>.scorecard.json` equal `dumps(validate(design).to_dict()) + "\n"` (use the module's own `dumps` and `validate`).
3. `test_rows_json_failure_does_not_break_index` (monkeypatch `hangar.index.rows_json` to raise): `entry["rows"] is None`, no `.rows.json` file, `entry["scorecard"]` still set.
4. `test_rows_have_text`: every row with status not PASS has non-empty `title` and `sentence`.
