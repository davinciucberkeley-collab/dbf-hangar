## Exact steps
1. `pdledit.py`: new `def replace_list(text: str, key: str, new: list) -> tuple[str, list, list]` returning (patched text, old list, new list). `key` names an existing one-line flow list `[...]` (reuse `_one_line_list(lines, root, key)`; any other case: the same errors as `_edit_list`: "is not a list" / "is not a one-line [list]; ... edit the file by hand"). `new` must be a non-empty list (else OpInputError `"<key>: new list must not be empty"`); its text is `render_flow(new)`; only the text between the old `[` and its matching `]` (inclusive) is replaced; verify with `yaml.safe_load` equality against the old data with the list assigned, and that only that one line differs (as `_edit_list` does); CRLF preserved. Works for a vector inside a flow element (`- {id: a, position: [1, 2, 3]}`) and in a block element (`    position: [1, 2, 3]`).
2. `pdledit.py::remove_element`: replace the `if seq.fa.flow_style(): raise OpInputError(hand)` branch by a one-line flow-list removal: every item of `seq` must start on the same line (`seq.lc.item(k)[0]` equal, else the `hand` error); item `i`'s span starts at `seq.lc.item(i)[1]` and ends at the matching close for a `{`/`[` item (`_close_brace(line, col) + 1`) or at `_TOKEN.match(line, col).end()` for a scalar; remove the item and one separator exactly as `_edit_list`'s removal branch does (not last: item through the start of the next item; last: from the preceding comma through the item end; only item: the whole inside of the brackets). Keep the existing result checks (`yaml.safe_load(out) == expected`; one changed line). Block lists keep their current code path (unchanged bytes).
3. `ops/edit.py::set_op`: in the per-pair loop, when `kind == "modify"` and `raw.strip()` starts with `[` and ends with `]`: `new = pdledit.parse_value(raw)`; if the existing value at `k` (via `pdledit.get_value`) is not a list -> OpInputError `f"{k}: is not a list; give one scalar"`; unchanged (equal) -> same "unchanged" shortcut as scalars; else `working = pdledit.replace_list(working, k, new)[0]` and the log entry carries `old`/`new` as lists. Every other path (scalars, `--kind add`, `--append`, `--remove`) is unchanged. Update the `set_op` summary string: after "Change, add or remove values" add ` (a [list] value replaces an existing one-line list, for example a position)`.
4. `ops/batch.py`: the `set` verb accepts a list value: when `value` is a list, require the existing value to be a list (OpInputError `"edit n: <key> is not a list"` otherwise) and call `pdledit.replace_list`; a scalar value behaves as now; a dict value keeps the error `"edit n: set takes a scalar or a list; use add or append"` (update that message from "set takes a scalar; use add or append").
5. `tests/test_design_apply.py`: in `test_shape_errors` the line that expects `{"set": "components[wing].position", "value": [1, 2, 3]}` to fail with a message containing `scalar` becomes `{"set": "components[wing].mass_g", "value": {"a": 1}}` failing with a message containing `scalar or a list`. No other edit to that file.
6. Regenerate `docs/cli.md`.
