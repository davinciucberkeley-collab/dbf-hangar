## Exact inputs
- `core/hangar/ops/__init__.py` (`op` decorator line 141: raises `ValueError` on a duplicate name; `registry()` line 152: imports every `hangar/ops/*.py` module once, `_LOADED`)
- `tests/test_ops_contract.py` (`ops`, `pytest`, `registry` already imported; append at the end of the file)

- Problem (ledger T3): a module registers some ops, then fails mid-import (for example a missing optional dependency). `registry()` raises, `_LOADED` stays False, and the next call re-imports the module: the already-registered names hit `duplicate op name`, which hides the real error.
- Fix: in `registry()`, snapshot the registry before each module import; if the import raises, delete the names that module added, then re-raise. A retry re-runs only the module that failed (modules that imported fine stay cached in `sys.modules` and keep their ops). The `duplicate op name` check in `op()` is unchanged.
- The test writes a throwaway module `zz_flaky.py` into a temp folder, adds that folder to `hangar.ops.__path__` with `monkeypatch`, makes the first import raise through an env var, and cleans up in `finally`.
