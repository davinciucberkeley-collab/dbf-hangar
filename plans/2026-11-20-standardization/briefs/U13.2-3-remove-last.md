## Why (red on main)
`design set --kind remove "attachments[x]"` on a list with one element fails with `cannot remove this element without rewriting other text; edit the file by hand`, because deleting the lines leaves `attachments:` (null) and `yaml.safe_load(out) != expected` (`[]`). So no list can be emptied. Removing many elements at once already works: `--kind remove KEY1 --also KEY2= --also KEY3=` is one atomic call (one ~7-15 s regeneration); do not add a new bulk op.

## Exact steps
1. `core/hangar/pdledit.py::remove_element`: when the element is the only item of a block-style list (`len(seq) == 1` and not `seq.fa.flow_style()`), build the result directly instead of deleting lines: let `h` = the 0-based line of the list's `key:` header (`parent.lc.key(name)[0]` on the parent mapping that `walk` returns for `steps[0]`; the header line must match `^\s*<name>:\s*(#.*)?$`, else raise the existing `hand` error); output lines = `lines[:h] + [<indent>name: []<comment suffix kept if the header had one>] + lines[h+1:first] + lines[last+1:]` where `first` and `last` are the element's first/last lines computed exactly as today (including the preceding comment lines that begin with the id). Then the existing `yaml.safe_load(out) != expected` guard applies; skip the `SequenceMatcher` opcode loop only for this case (its construction is explicit). Every other path stays byte-for-byte as is.
2. `core/hangar/ops/edit.py`: change nothing but the `design.set` summary: append the sentence ` Removing a list's only element leaves an empty list ([]).` at the end of the summary string (before the closing quote).
3. Regenerate `docs/cli.md`.
