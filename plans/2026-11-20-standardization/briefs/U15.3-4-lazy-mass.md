## Exact steps and outputs
1. `core/hangar/geom/resolve.py`
   - Move the final loop of `resolve_design_data` (from `design_materials = ...` to the `return`) unchanged into a new function `fill_generated_mass(data: dict, base_dir: Path, errors: dict[str, str]) -> None` (mutates `data` components and `errors`).
   - New signature `resolve_design_data(raw: dict, base_dir: Path, *, mass: bool = True) -> tuple[dict, dict[str, str]]`. With `mass=True` (default) it calls `fill_generated_mass` last: behaviour identical to today. With `mass=False` it skips it (so `mass_g` of generated parts is absent and `errors` holds only hinge and cut-sweep errors).
   - In `regeneration_report`, replace the two lines `om, ocg = _aircraft(old, ...)` / `nm, ncg = _aircraft(new, ...)` by: compute them only when `comps` is non-empty; otherwise `om = ocg = nm = ncg = None`. The returned dict keeps the same keys. (Every reader prints `mass_g`/`cg_mm` only inside `if regen["components"]`: `ops/edit.py:154`, `ops/batch.py:118`.)
2. `core/hangar/design.py`
   - `Design` keeps its dataclass fields and constructor signature unchanged (`Design(data, path, raw, resolve_errors)` is built in many places). Add a private mechanism so that, when `load_design` creates a design with `design.raw` set, `design.data` is the resolved data WITHOUT generated mass, and the first read of `design.data`, `design.components`, `design.component(...)` or `design.resolve_errors` runs `fill_generated_mass` once on that same dict object (identity preserved; `design.data is` the same dict before and after) and merges its errors into `design.resolve_errors`. Suggested mechanism: a `_mass_pending: bool` instance flag plus `__getattribute__` for the two names `data` and `resolve_errors`; any mechanism is fine if the tests below pass and the constructor and `dataclasses.replace`/`copy` behaviour used in `core/` and `tests/` is unchanged (grep `replace(design`, `copy.copy(design`, `deepcopy(design` first; name the hits).
   - New method `Design.data_without_mass(self) -> dict`: returns the resolved data without triggering the mass fill (same dict object; once filled it is the filled dict).
   - `load_design`: call `resolve_design_data(data, design.base_dir, mass=False)` and set the pending flag; everything else unchanged. A design without generators or parameters never sets the flag.
3. `core/hangar/ops/design.py`, `get_op` only: with an empty `key`, do not read `design.data` at all; with a non-empty `key`, use `design.data_without_mass()` unless the key's first segment (the part before the first `.` or `[`) is `components` or the key contains `mass_g`, in which case use `design.data` as today. Output dict unchanged.
4. Do not change `_aircraft`, `generated_volumes`, `mass.py`, `checks.py`, or any caller of `load_design`: they read `design.data`/`design.components`, which complete the mass on first read.
