## Facts (tactician, verified on main ed243d5)
- Audit symptom: `ValueError: string is not a file: ...\.sweeps\concept-a\2\meshes\avn-001.stl`. The CLI accepts repeated `--values` (`plane design sweep --help` shows `--values TEXT [required]`, a repeating option), so the guide example `--values 1.0 --values 1.2 --values 1.4` is correct. A clean single run does not crash: `plane design sweep designs/concept-a flight.cl_max --values 1.0 --values 1.2` succeeded (2 m 15 s); `example-tailsitter-wing` with 3 values succeeded in 8 s.
- Cause (reproduced): `sweep_op` writes to the fixed folder `<REPO_ROOT>/.sweeps/<design id>/<n>` and starts with `shutil.rmtree(root)`. `REPO_ROOT` is taken from the installed package location, so every worktree, test run and agent on the machine shares the MAIN checkout's `.sweeps/`. A second sweep of the same design id deletes or half-recreates the first run's copies while it is still validating them. Two `concept-a` sweeps started 25 s apart: the first finished, the second died with `FileExistsError: ... .sweeps\concept-a\2`; when the deletion lands between the copy and the mesh load, the first run raises trimesh's "string is not a file" for `...\2\meshes\avn-001.stl`.
- Existing tests that read the layout: `tests/test_design_edit.py:129` (`tmp_path / "sweeps" / "example-tailsitter-wing" / "1" / "plane.yaml"`), `:134` and `:136` (`.sweeps/example-tailsitter-wing/1/plane.yaml` and `sweep_dir == .../.sweeps/example-tailsitter-wing`). `tests/test_pdl12.py::test_sweep_over_a_parameter` and `tests/test_concept_a_param.py::test_sweep_over_span` monkeypatch `hangar.ops.edit.SWEEP_ROOT` and read only `rows`; they must keep working. `.sweeps/` is git-ignored.

## Decision (the conductor may overrule before the build; if told otherwise, follow that)
Each run gets its own folder: `root = _sweep_root() / did / f"{UTC %Y%m%dT%H%M%S}-{os.getpid()}"`, copies at `root/<n>`; `sweep_dir` returns that run folder. Remove the whole-`<did>` `rmtree`. After creating the run folder, prune best-effort: every sibling folder under `_sweep_root()/did` whose mtime is more than 24 h old gets `shutil.rmtree(sibling, ignore_errors=True)`; a younger sibling is never touched.
