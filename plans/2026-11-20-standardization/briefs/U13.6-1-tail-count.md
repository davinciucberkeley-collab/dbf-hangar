# Brief U13.6-1-tail-count: a tail built from fixed + elevator + rudder components counts once in tier 3

class: hard · role: builder-plus · plan: §7 U13.6 item (6) · depends on: U13.3-1 (merged), U13.3-4b (merged) · merge order: 1st · SLUG = `tail-count`

Environment: follow `plans/2026-11-20-standardization/briefs/U13.6-env.md` with SLUG=tail-count.

## Finding (investigated 2026-11-24 on main, CAD overlay off)
`T3.static_margin` is too high on both rehearsal designs because the same stabiliser is counted three times. `core/hangar/geom/planform.py::generated_planform` derives the stabiliser outline from `stab_*` params for EVERY `tail_surfaces` component of type `tail_surface`, whatever its `part`. Both rehearsal designs split the tail into three components with identical params (`part: fixed`, `part: elevator`, `part: rudder`), so `_tier3` adds three tails (the rudder one too, although a rudder is not a lifting stabiliser).
- C172 (`rehearsal2-c172/designs/c172-rc`): `T3.static_margin` 59.9 % MAC, NP x = 362 mm. With one stabiliser counted (patched in a script, nothing committed): 7.8 % MAC, NP x = 292 mm, PASS in the 5-25 % band.
- A400M (`rehearsal2-a400m/designs/a400m-rc`, T tail): 150.2 % MAC, NP x = 1055 mm. With one stabiliser: 59.3 % MAC, NP x = 873 mm. The remaining 59 % is real for that model, not a bug: tail volume about 0.9 with a stabiliser lift slope close to the wing's puts the neutral point near 0.7 MAC, the design's CG (x = 753 mm) sits about at the wing's aerodynamic centre, and the check says "fuselage effect not modelled" (a fuselage moves the NP forward). It needs a CG move or a smaller tail, not a code change.
- Hand check of the C172 single-tail number: wing S = 192,514 mm2 (rectangular 274 mm inboard, taper 177 to 116 over 326 mm, both sides), AR 7.48, Helmbold slope 4.824, downwash factor eps = 2 a/(pi AR) = 0.4106, wing MAC 162.9 mm, wing x_ac = 212 + 0.25 x 162.9 = 252.7 mm; stabiliser S = 41,002 mm2 (355 x (131+100)/2), AR 3.07, slope 3.408, MAC 116.2 mm, x_ac = 698 + 14.95 + 29.05 = 742.0 mm; k_tail = 3.408 x 41,002 x 0.9 x (1 - 0.4106) = 74,121, k_wing = 4.824 x 192,514 = 928,688; NP = (928,688 x 252.7 + 74,121 x 742.0) / 1,002,809 = 288.9 mm (the check measures the wing from the mesh and gets 292). Counted three times, k_tail is 222,363 and NP = 362 mm, which is the reported number.
- Not the same mechanism: the dry-run of concept-a-reborn (`u4.40/dryrun-log.md`, B7) has an imported MESH wing with a declared planform, whose measured area is 71,618 mm2 against 220,500 declared (-67.5 %) and static margin 116 % MAC. That design has no generated tail; the measured strip path (`strip_planform`, "the chord is the longest merged group" per strip) under-measures a core with 117 cuts and a separate skin component (WNG-011, WNG-012). It cannot be reproduced here (the design is not in the repo) and is not fixed by this brief; the `surfaces` data added below shows its measured area per surface so the cause can be seen.

## Exact steps
1. `planform.py::generated_planform`: for `tail_surfaces`, return `None` when `p["part"] == "rudder"` (a rudder is not a stabiliser). For parts `full`, `fixed`, `elevator` return the same dict as now (the outline params describe the whole stabiliser).
2. `planform.py`: new `def counted_tail_ids(components: list[dict]) -> set[str]`: group the components that have `generated_planform(c)` with a `lifting_surface` key by a signature `json.dumps([sorted((k, v) for k, v in params.items() if k.startswith("stab_") or k in ("layout", "airfoil_file")), c.get("position"), c.get("rotation_deg")], sort_keys=True, default=str)` where `params` are the defaults-filled generator params (use the same `fill_defaults(get("tail_surfaces"), ...)` as `generated_planform`); within each group keep ONE component id, chosen by part priority `full`, then `fixed`, then `elevator`, ties by component order. Return the set of kept ids. Components with no group mate are kept.
3. `checks.py` `_tier3`: before the surface loop, `counted = counted_tail_ids(design.components)`; in the derived branch, when `gp` has a `lifting_surface` key and `c["id"] not in counted`, `continue` (nothing else in the loop changes; the measured wing branch is untouched).
4. `checks.py`: the `T3.static_margin` row's `data` dict gains `"surfaces": [{"id": <component id>, "area_mm2": round(area, 1), "x_ac_mm": round(x_ac, 1), "source": "measured" | "derived" | "declared"} for each lifting surface used, in the order of `lifting`]` (`measured` for strip_planform, `derived` for a generated tail, `declared` for a hand `lifting_surface` geometry or planform wing; use `main_from_planform` and `derived_tails` that already exist to decide). The row text (message) does not change.
