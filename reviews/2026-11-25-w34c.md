### Lazy proxy behaviour (asked by the conductor)
- **isinstance checks:** `isinstance(x, trimesh.Trimesh)` is attribute access on the proxy, so it returns the real class and behaves the same. Nothing in `core/` tests the module object itself (no `ModuleType`/`inspect.ismodule` hit).
- **Annotations:** every touched file has `from __future__ import annotations`, so annotations like `-> trimesh.Trimesh` and the module-level `_BASE_PARTS: dict[str, list[trimesh.Trimesh]]` (`geometry.py:110`) are strings and never evaluated. I grepped for module-level code, default arguments, decorators and class bases that use `trimesh.`: only annotations matched, so nothing loads trimesh at import.
- **Exceptions at first use:** a missing or broken trimesh now raises `ModuleNotFoundError` at the first `trimesh.X` inside a function instead of at import. Inside a gate's `except Exception` (e.g. `run_gates`) that becomes a `T<n>.error` FAIL row instead of a crash. trimesh is a hard dependency, so this only matters in a broken environment. Test 3 pins the raise.
- **Tests that patch trimesh:** `tests/test_perf_caches.py:44,101` patch the real `trimesh` module (imported directly in the test), and the proxy forwards to it, so the patches still take effect (the tests pass).
- **Package attributes:** `import hangar` no longer imports `.design`, `.checks` and `.mass`. Code that does `import hangar` and then reads `hangar.checks.X` without importing the submodule would now get `AttributeError`. The only such use, `tests/test_design_edit.py:480`, already imports `hangar.design` and `hangar.gates` through other imports, and CI shards 1 and 3 pass. Shard 2 still has to confirm.
