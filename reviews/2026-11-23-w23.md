### Non-blocking suggestions
1. **S1 (major, U4.22 or the reopen):** T0.generator PASS says "build watertight" for generated components that were never built. `resolve_design_data` builds only generator components that have `mass_model` (resolve.py:59, as the brief specifies). A generator component with `mass_g` and a bad build (probe: missing `mesh_file`) therefore passes tier 0 with the message at checks.py:97. Either build every generator component when resolving, or limit the PASS message to the components that were built. No criterion covers this yet, so it is a suggestion.
2. **S2 (minor):** The T0.parameters PASS at checks.py:68 counts references as "resolved" even when the parameter value is not a number. T0.schema catches that case, so nothing slips through, but the message is wrong.
3. **S3 (major, U4.22):** `fea.part_hash` hashes a generator's geometry dict but not the bytes of its `component_files` (fea.py:225-226, per the brief text). Editing the STL behind a `mesh_file` generator therefore does not invalidate FEA results, unlike the `geometry.mesh` branch. Add the `component_files` paths to `files`.
4. **S4 (minor):** The mass from `mass_model` uses `build_component` volumes, which ignore `cavities` (resolve.py `generated_volumes`). Geometry, export and interference use `_base_parts`, which subtracts them. A generated part with cavities gets the mass of the uncut solid. Either forbid cavities on generator components or use the cut volume.
5. **S5 (minor):** Duplicated logic. The `resolve._key` / `_VOLUMES` cache repeats the stat-keyed cache in `geometry._base_key` / `_base_parts`. `materials._FILE` (materials.py:13) computes the repo root itself instead of using `hangar.design.REPO_ROOT`.
6. **S6 (minor):** `set_op` returns `data["regenerated"]` only when some component regenerated (edit.py:136), while the brief says "when regen is not None". The test accepts either. `regeneration_report` refuses any edit while any generated part in the new text fails (resolve.py:103), even an edit unrelated to that part. That matches the brief; document it for users.
7. **S7 (minor):** `_aircraft` (resolve.py:87) swallows every exception and reports "n/a". Narrow it so a real mass-model bug is not hidden.
