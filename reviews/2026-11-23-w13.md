### Echo or recomputation (the key question)

Measured, not assumed (reviewer script over `designs/concept-a/claims.yaml` and `plane.yaml`):

1. All 40 read_value calculations take one input `v: P:<path>`, and all 40 of those ids are parameter nodes with a constant `value` in `claims.yaml` (imported from `redesign/qp/A/params-A.json`), not PDL paths. graph.py:201-203 returns that constant; graph.py:145-146 forbids the same id from also resolving in `plane.yaml`, and `plane.yaml` has no `mass.cg_x_mm`, `struct.*`, `sim.*` or `cad3d.*` leaf. The echo reads the imported number, not the live design.
2. For all 40, parameter `value` == claim `value` == calculation `outputs.v` (the importer wrote all three from the same source). The STALE comparison (graph.py:281) is therefore equal by construction; it fires only if a future re-import writes them inconsistently.
3. What the run does check: the stored value against its limit. 35 limits are `ref`s to parameter constants (`P:req.*`, `P:struct.landing_stroke_max_mm`, `P:cad3d.*`; also imported), 3 are literal `0`, 1 is a claim (`CL-A-DIVERGENCE >= CL-A-FLUTTER-LINE`, a real `flutter_line` calc), and 1 has no limit (`CL-A-FLUTTER-HALF`: PASS "computed, no limit", information only).
4. Traceability holds: `plane claim explain designs/concept-a CL-A-MS-SPAR` prints claim, then `CALC-A-MS-SPAR-READ` ("Stored result: ..."), then `P:struct.ms_spar`, then `SRC-A-ITER2M` (iter2_margins.md). All 40 parameters carry a `source: SRC-A-*`; each calculation's `equation` says "read, not recomputed" or "read, not re-run".

Answer: `read_value` is an echo, not a recomputation. It is not a trivial pass either: a value outside its limit FAILs (graph.py:271-272), and the trace to a named source is intact. It does not re-run the CAD mass, SITL, FEA-margin or collision analyses, and it does not tie the value to `plane.yaml`. Under `standards/review-scorecard.md` "Evidence and closure" ("call an untested result a pass on paper only" [J6#7]; "give every figure a unit, a source and a status label" [J4#2]) these 40 are passes on paper: sourced stored results that meet their limits.

PASS versus a distinct status: `plane claim list` prints `CL-A-MS-SPAR PASS 2.73 - +2.73 abs` in the same form as `CL-A-SM PASS 7.890331848236766 % chord +57.8%` (a real `static_margin` recomputation), so the status alone no longer tells a reader which claims were recomputed. Within existing graph semantics PASS is consistent (every other calc already treats a sourced parameter constant as a confirmed input; a claim with no calc still stays PROPOSED, graph.py:283-284, untouched). A distinct status (for example READ: "value read from its source, compared with its limit, not recomputed") would be more honest, but it needs `graph.py`, `schema/claims.schema.json`, the T9 gate mapping and baseline semantics, which D59 did not ask for and the brief forbids. Not picking a side: flagged for `advisor` (suggestion 1). It is not a defect of this branch, which does what the plan and brief specify and calls itself an echo in its docstring.
