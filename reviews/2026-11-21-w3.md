A tier's status is FAIL when any of its checks fails (design.py:59-62), so every tier-1 row shows FAIL and the check's own status is only the prefix of the Result cell. The line dates from the seed commit 6909134, so it is on main and not caused by U3.2. Effect: the brief's filter `plane design validate ... | grep -v "| PASS |"` cannot drop PASS rows inside a failing tier, and an agent that reads the Status column for design-iterate step 1 ("list every FAIL, WARN and SKIP check id") would list passing checks. It does not block U3.2 (the skill text is correct; the defect is in core). It is a separate pre-existing defect: suggest a ledger task to render `r.status` in that column (or rename the column "Tier status"), with a test.
