### Blocking issues
1. **The gate trusts the name, not the built-in.** `harness/hooks/agent_gate.py:83-84` returns 0 for any `subagent_type` in `("Explore", "Plan", "claude-code-guide")`, before the roster check. Per sub-agents.md ("A user or project subagent named `Explore` overrides the built-in"; scope priority table), a definition with one of these names replaces the built-in:
   - in `~/.claude/agents/`, recursively;
   - in a plugin;
   - from `--agents`;
   - in the project's `.claude/agents/`.

   Such a definition can carry any tools. One with no `tools` line inherits Write, Edit and Bash. The docs even suggest defining your own `Explore`. With this branch, a teammate's user-level `Explore` with full tools skips the roster, agent-table and builder-ready checks.

   Before this branch, the gate refused every one of those names, and a user-level agent could not override a project roster role, which has higher priority. This is a new bypass, against U4.20 "Rules and hooks must stay enforced" and D66/T112, which allow the read-only built-ins only.

   Suggested fix, for the tactician to brief: allow a built-in name only when no definition with that `name:` exists in the project `.claude/agents/` or `~/.claude/agents/`, scanned recursively. Add a test with a fake user agents dir, for example by pointing `HOME` or `USERPROFILE` at a tmp dir. Record the plugin and `--agents` overrides as residual risk in the comment, or decide to accept them. Whether that residual risk is acceptable is the conductor's call.
2. **The comment states a premise the docs do not support.** `harness/hooks/agent_gate.py:10` says "tools cannot write files (no Write, Edit or Bash)". sub-agents.md says only "read-only tools; Write and Edit are denied" for Explore and Plan. tools-reference.md says searches run through Bash on macOS, Linux and WSL. Bash is bounded by the inherited permission rules and hooks, not removed. The docs give no tool list for claude-code-guide.

   The comment is the security rationale for the allow-list, so it must be accurate. For example: "Write and Edit denied; Bash, if present, runs under the parent's permission rules and hooks."

### Non-blocking suggestions

2. `docs/team-guide.md` and `standards/agents.md`, as changed on branch a, call the three agents "read-only". That matches Anthropic's wording; keep it, but see blocking issue 2.
