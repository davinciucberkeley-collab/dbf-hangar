### 1. Expression grammar and evaluation
- Any string under REF_PATHS that contains `$` is an expression; a whole-string `"$name"` keeps the current fast path (same value, same type). Grammar: `expr := term (("+"|"-") term)*`, `term := unary (("*"|"/") unary)*`, `unary := "-" unary | atom`, `atom := NUMBER | "$" name | "(" expr ")"`. NUMBER is a decimal with an optional exponent; name is `[a-z][a-z0-9_]*` and must be a key of `parameters` with a numeric value. Nothing else: no bare names, no `**`, no calls, no attributes, at most 200 characters. Hand-written tokenizer plus recursive descent in `geom/params.py` (about 60 lines); no `eval`, no `ast` evaluation.
- Result: float, returned as int when integral (so `450 - $span_mm/2` at 900 gives `0`, identical to the current file and the baselines).
- Errors: unknown or non-numeric name, syntax error, division by zero. `find_references` returns every (component, path, name) inside an expression, so `T0.parameters` reports unknown names as now; an expression that does not parse or divides by zero is a new `T0.parameters` FAIL row with its path. `design set` refuses an edit that newly produces one (same rule as `regeneration_report`: refuse only what this edit breaks).
- Extend REF_PATHS to `attachments[*].location` and `attachments[*].articulation.pivot` (body-frame points that must follow their parts; 58 of the 142 concept-a-param joints touch moved parts, 4 of them articulated). Schema text (1.2 description, `parameters`, position/location descriptions) says "number, or a string expression over parameters"; validation keeps running on resolved data (`pdledit._errors` and tier 0 already resolve first), so the JSON schema needs no new type.

### 2. Relative placement: choose (b), expressions in positions
- (a) `position_ref: {parent, frame, offset}` does not fit the data. Attachments carry only a `location` point (no orientation frame); every concept-a-param mesh part sits at `position [0,0,0]` with geometry already in the body frame; and the parents that change are the *generated* wing core wng-001 and spar wng-002, which change shape and do not translate. The tip is not a frame anywhere today, so (a) also needs generator-published anchors (wing_panel tip_l/tip_r), a dependency-ordered resolver with cycle detection, relative attachment locations, and pose code in T1/T6 that composes frames. Estimate 4-5 days and new failure modes; not doable by Sun 12:00.
- (b) `position: [0, "450 - $span_mm/2", 0]` (left; right `"$span_mm/2 - 450"`), tube `center: [$fin_x_mm, "$span_mm/2 - 70", 0]`, joint locations such as `"-379.846 + 450 - $span_mm/2"`. Reuses the existing resolve path, needs no ordering or cycles, keeps every part visible in `design get/diff`. About 1 day of core plus tests; the conversion is data. Weak point: 112 values to write, mitigated because T1 catches a missed joint (E2) and a missed part (A, B).
- D75 words the mechanism as positions relative to the attachment frame of the parent part. (b) meets the intent (children follow the tip) with a different mechanism; the conductor should record that. (a) can come in v1.1 as an authoring shorthand that compiles to (b).

### 3. Reporting interference after a regenerating set
- Generalise `regeneration_report`: run when the old or new raw design has `parameters` (not only generators). Changed parts = every component whose resolved signature (geometry, position, rotation_deg, resolved cut transforms) differs, plus every attachment whose resolved location/pivot differs.
- Add an optional `only: set[str]` argument to `checks._contact_and_clash_checks` that keeps only interference pairs and attachments involving a part in `only` (one implementation, not a second checker). Run it on old and new data (static pose, identity transforms; poses stay with `validate`). Report rows present in new but not old, matched on (check_id, sorted pair or joint id), as `data["interference"] = {"moved": [...], "new": [...], "cleared": [...]}` plus one message line per new row, e.g. `new interference: fin-002-l and wng-006-l overlap 764 mm^3`.
- **Report, never refuse.** The design-engineer resolves collisions next; refusing would make a span change impossible to stage. Keep refusal only for a newly broken generated part or a newly invalid expression. Budget: the set may take up to about 15 s on concept-a-param; measure and state it in the PR.
