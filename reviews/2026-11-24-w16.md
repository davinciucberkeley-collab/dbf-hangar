### Security (caller's question: can an agent with only `Bash(plane *)` now defeat the replay?)
- **Option values: yes, through `design new --template` / legacy `new --from`.** The brief's premise "design.new has none [no path argument]" is wrong in effect. `cli.new_design` (`core/hangar/cli.py:142`) does `src_dir = DESIGNS_DIR / template` and never checks `template` against `ID_RE`, so an absolute (or `../`) template is a path. Before T101, `_map_args` mapped every existing non-dash word, including the word after `--template`: an in-workspace template went to `replay/...`, and one outside the workspace was refused. After T101 option values are "never checked" (`bench.py:212`, and the test at `tests/test_bench.py:292` asserts it), so the replay copies the template from wherever the agent pointed. That can be the agent's own workspace outside `designs/`, which `designs_diff` does not compare and the snapshot digest does not cover.
  Probe (combined tree, scratch dir only, no `bench run`, no `claude`): `ws/.sweeps/concept-a/1/plane.yaml` held content that is not in the snapshot (`name: TAMPERED`). The agent-side command `plane design new foo --template <abs ws/.sweeps/concept-a/1>` (logged through `PLANE_BENCH_LOG`) created `ws/designs/foo` with `name: 'TAMPERED (copy: foo)'`. `bench.replay(ws, snap, log, tree_digest(snap))` returned `[]`, so the run passes. `_map_args` left the absolute template unchanged. `replay_kind(design sweep ...)` is `skip` and `replay_kind(new foo --from ...)` is `replay` with `_path_positions` = set(). So within `Bash(plane *)` alone, `design sweep` (which T101 itself moves into `<ws>/.sweeps`) followed by `design new --template <abs sweep dir>` gives a design whose changes have no `design set`/CHANGELOG entry, and the replay accepts it. With shell redirection (the open probe), the content is arbitrary.
  It also breaks a legitimate run: `design set bar ...`, then `design new foo --template <abs ws/designs/bar>`, then another `design set bar ...` replays `foo` from the final `bar` and fails. (The `--template=<abs>` one-word form was already unchecked on main, because `_map_args` skipped dash words. T101 extends the gap to the two-word form and pins it with a test.)
- **Forged but well-shaped log line:** not reachable within `Bash(plane *)` without redirection. Only `_log_invocation` writes the log; `json.dumps` escapes newlines in argv, so one invocation cannot add a second line. No plane command that `replay_kind` lets through (skip or replay) writes a file at a path the agent chooses: `validate --out`, `export --out` and `--`-prefixed forms are refused, and a refused command fails the whole run. As the brief says, a forged line that keeps the shape is not detected; that rests on the open redirection probe.
- **Sweep writes:** contained. `_sweep_root()` puts them under `<ws>/.sweeps/<design id>`, and the id comes from the source design's `id`, which the schema limits to `^[a-z0-9][a-z0-9_-]*$`. Nothing writes to the real repo. Their only effect on the replay is as a template source (first bullet).

### Blocking issues
1. `core/hangar/ops/bench.py:183-212` with `core/hangar/cli.py:142`: `design new --template` and legacy `new --from` take a path, but after T101 the replay neither maps nor checks it. The replay then reads a folder in the agent's workspace (or anywhere) instead of the fresh snapshot copy, and a run whose design did not come from the snapshot plus replayed `plane` commands passes (probe above). Criterion: the replay contract in the `bench.replay` docstring and T54/D56/T92 (designs/ must equal a replay of the logged commands on a fresh copy of the snapshot; a path outside the workspace is refused). The brief's default "design.new has none" leads to this, so per the reviewer stop rule I flag it for `advisor` and do not pick the fix. Candidate fixes: (a) `new_design`/`design.new` require `ID_RE.fullmatch(template)` (the CLI help already says "Design id to copy from"; one line plus a test, and both commands go through it); or (b) `_path_positions` also flags the `template` option value. (a) also closes the existing `--template=` form. A test should pin that `new foo --template <abs path>` is refused or mapped.

### Non-blocking suggestions
1. `PATH_PARAM_NAMES` keys on parameter names (`path`, `src`). A future replayable op with a differently named path parameter would silently go unmapped. Consider declaring path-ness on the op (`type_name == "path"`, i.e. annotate `path: Path`) and dropping the name list.
2. `tests/test_bench.py:292` asserts "an option value is never checked" with an absolute path outside the workspace. After the blocking fix, keep that assertion for `--value`/`--why` only.
