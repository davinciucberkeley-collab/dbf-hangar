### Builder flag: body key `name` gives 500
Reproduced: POST `/api/op/design.mass` with body keys `path` and `name` gives **500** with `{"error": "TypeError: call() got multiple values for argument ..."}`, which is not OpResult JSON. Switching Studio to `_call_spec(registry()[op], **params)` only moves the collision: a body key `spec` already gives the same 500 through `_call_spec`. MCP is safe today, because its tools take only declared public names (an extra kwarg returns an input-error OpResult). **The root cause is the U1.1 signatures, `call(name, **params)` and `_call_spec(spec, **params)`**. The fix is to make the first parameter positional-only (`def call(name, /, **params)`, `def _call_spec(spec, /, **params)`). That change is in `ops/__init__.py`, which is outside the U1.2 Where, and it does not change the interface for callers. Without it, any future op with a parameter called `name` (Studio, MCP) or `spec` (CLI too) would break. **Ruling: log it, do not fix it in U1.2.** Do it as a small ops follow-up before an op with a `name` parameter lands (U1.4 or U1.5 likely). Only a malformed local request reaches it today.
